# Independent Orchestrator driver verification

These tests use the real state service, authenticated internal command transport, immutable artifact staging/readback, and O2 Git storage. The bounded fake runtime follows F1's flattened launch records, explicit observer outcomes, physical worker status/stop replies, archive-seeded private repositories, registered canonical bindings, and immutable snapshot materials. It launches no model or container.

The initial backend failed the actual `orch_task_settle` request because the driver omitted its run and owner binding. Source review also identified candidate `commit`/`resultCommit` shape disagreement and an assembler task lookup despite its run-wide role. Replaying the backend author's repair exposed a further first-fix/first-work attempt identifier collision. The author repaired these seams, exact candidate source bindings, and current-worker settlement selection.

The full regression drives decomposition, ready-task admission, physical worker settlement, real import and evidence publication, a verifier return, a distinct fix preserving prior bytes, acceptance, a dependent snapshot containing the fixed ancestor, assembly from the durable predecessor diff bundle, explicit integration declarations, and materialization into the validation workspace. It verifies the handoff to `awaiting_validation`; the shared U5 scheduler and live model acceptance remain separate checks.

Focused lifecycle cases cover lost-bind recovery from the actual flattened launch shape, observer timeouts preserving live attempts, cancellation request refusal/retry, and a failed physical stop preventing terminal completion until namespace settlement is proven.

Live restart subsequently exposed a separate run-owner gate: after all tasks were accepted, a replacement runner could never issue the assembler because only attempt ownership supported adoption. The driver now obtains an exact dead-owner proof through the scheduler's existing proof helper, submits the authenticated `orch_claim`, and reloads the durable record before doing any bookkeeping or issuing work. The existing domain verifies environment, PID, starttime, and a positive dead-process finding; lease age alone grants no permission. The regression parks a completed graph before assembly and verifies no-proof, mismatched-PID, and live-process claims fail closed, while a matching dead-process proof adopts and launches exactly once.
