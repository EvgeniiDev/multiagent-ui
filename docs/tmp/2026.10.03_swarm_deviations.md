# Swarm S1/S2 deviations — 2026.10.03

Scope: `server/execution/swarm/protocol.mjs`, `server/execution/swarm/edit-broker.mjs`,
`scripts/test_swarm_protocol.mjs`, `scripts/test_swarm_edits.mjs`. No shared
domain/scheduler/state/UI/deployment files touched.

## D1 — Transfer consent is turn-free (expected)

- Expected: plan says transfers need owner+recipient consent but rejects them
  during an active turn — consent itself needs a turn, which would make
  completion unreachable.
- Observed: two-party `request/consent` with lease auth could never complete.
- Action: `request_transfer`/`consent_transfer` authenticate by registered
  identity; completion re-checks neither party holds an active turn.
  Rule preserved (no transfer completes mid-turn), mechanism made workable.
- Risks: parent must ensure identity auth maps to real participants (it does —
  unknown participants rejected; only transfer parties may consent).

## D2 — Mid-apply crash stays BLOCKED instead of auto-rollback (expected)

- Expected: recovery "completes/rolls back per journal".
- Observed: `prev.bytes` are intentionally NOT journaled (multi-MB blobs would
  bloat the journal), so after a real process death the broker cannot
  surgically restore overwritten bytes.
- Action: `recover()` reports `rolled_back_noop` when nothing applied, else
  writes `blocked.json` and returns `blocked[]` with `crash_mid_apply` +
  applied-op count; the barrier stays closed until the parent reconciles.
  Same-process (non-crash) failures DO roll back in-process and thaw.
  This is honest non-toy behavior: never claims success, never silently
  loses the partial write. Test-only injected crashes skip same-process
  rollback so `recover()` exercises the genuine crash path.
- Risks: parent must handle `blocked[]` (surface diagnostics, reconcile,
  remove `blocked.json` before re-admitting readers). Documented in the
  contract file.
