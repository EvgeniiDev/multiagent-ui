# Swarm S1/S2 deviations — 2026.10.03

Scope: `server/execution/swarm/protocol.mjs`, `server/execution/swarm/edit-broker.mjs`,
`scripts/test_swarm_protocol.mjs`, `scripts/test_swarm_edits.mjs`. No shared
domain/scheduler/state/UI/deployment files touched.

## D1 — Transfer consent is turn-free (expected)

- Expected: plan says transfers need owner+recipient consent but rejects them
  during an active turn — consent itself needs a turn, which would make
  completion unreachable.
- Observed: two-party `request/consent` with lease auth could never complete.
- Action: `request_transfer`/`consent_transfer` authenticate by registered
  identity; completion re-checks neither party holds an active turn.
  Rule preserved (no transfer completes mid-turn), mechanism made workable.
- Risks: parent must ensure identity auth maps to real participants (it does —
  unknown participants rejected; only transfer parties may consent).

## D2 — Mid-apply crash stays BLOCKED instead of auto-rollback (expected)

- Expected: recovery "completes/rolls back per journal".
- Observed: `prev.bytes` are intentionally NOT journaled (multi-MB blobs would
  bloat the journal), so after a real process death the broker cannot
  surgically restore overwritten bytes.
- Action: `recover()` reports `rolled_back_noop` when nothing applied, else
  writes `blocked.json` and returns `blocked[]` with `crash_mid_apply` +
  applied-op count; the barrier stays closed until the parent reconciles.
  Same-process (non-crash) failures DO roll back in-process and thaw.
  This is honest non-toy behavior: never claims success, never silently
  loses the partial write. Test-only injected crashes skip same-process
  rollback so `recover()` exercises the genuine crash path.
- Risks: parent must handle `blocked[]` (surface diagnostics, reconcile,
  remove `blocked.json` before re-admitting readers). Documented in the
  contract file.

## 2026-10-03 independent review repairs (S1/S2)

The independent review found that the original progress markers were written
AFTER mutations, beforeimages lived only in memory, result publication could
trigger an incorrect rollback, and blocked transactions did not retain a real
reader barrier. The repaired broker journals binary beforeimages for every
path (both rename endpoints) and a durable started marker before touching the
tree. Actual process death before an applied marker now deterministically
rolls back; committed transactions only complete their indexes and outbox.
Rollback or publication failure retains a durable physical barrier and blocks
new submission and stop until recovery succeeds.

All tree operations now use Linux held directory descriptors through
`/proc/self/fd`, opening every ancestor with `O_DIRECTORY|O_NOFOLLOW`. Reads,
renames, replacements, chmod and rollback stay anchored; all file and directory
entries are fsynced. Atomic replacement avoids truncating shared external
inodes; hardlinked and nonregular leaves reject. Expected modes are enforced.

Trusted current lease, phase, explicit decision eligibility, and authoritative
ownership/version/reservation lookups are mandatory. Physical reader identity,
freeze and thaw hooks are mandatory. The parent must own one broker instance
per persistence root. Journal version is 2; unsupported version 1 journals
fail closed. Applied events have stable IDs and delivery can retry after a
process crash; the parent deduplicates those IDs. This replaces the former
manual-reconciliation limitation with automatic journal rollback.

Decision hashes now bind text, affected participants, and exact scope ownership
versions/consumers. Consumer/owner/registration changes create a new revision
and empty acknowledgement set; every participant must confirm the current
hash. The previous acknowledgements remain evidence only.

Validation includes actual SIGKILL in the mutation/marker window, failed
postcommit seen-index publication, failed result-directory fsync, retained
barriers across restart with rejected submit/stop, ancestor symlink swapping,
binary and overwritten-rename beforeimages, missing/forged authority, expected
mode, directory fsync before publication, and fresh decision acknowledgement
requirements. API wiring is published in `.agent-tmp/swarm-module-contract.md`.

Actual SIGKILL checks cover all five mutation kinds and the temporary-file
replacement window. The broker reserves `.swarm-` path segments; recovery
removes its UUID staging entries through held directory descriptors before
marking rollback complete.

The S3 controller may call `refreshSwarmDecisionBindings(initialState, now)`
after durable broker ownership changes. It returns a cloned state and emitted
events using the same binding logic, without forging expired participant auth.
Deleted scopes with no surviving owners become superseded; surviving scopes
require a fresh revision. A regression proves clone immutability and deletion
handling. Combined suite:42/42.
