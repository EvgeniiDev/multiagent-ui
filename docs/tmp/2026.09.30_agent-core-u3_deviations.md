## Runtime layer (common.mjs / porch-runtime.mjs / fake-runtime.mjs)

### D1. `existsSync('/proc/pid')` cannot implement EACCES-aware probing
- **Expected**: EACCES/hidepid-style probe failures are *unverifiable*
  (unknown), never "process absent".
- **Observed**: `existsSync` returns false on any error including EPERM.
- **Resolution**: errno-distinguishing `statSync` probe; `processIdentity`
  returns tri-state `exists: true|false|null`.
- **Status**: resolved — `EACCES-style unverifiable process probe blocks
  retry` self-test.

### D2. Missing launcher fields treated as "did not spawn"
- **Expected**: a durable `phase:'launching'` record written before spawn
  with neither launcher identity nor diagnostics stays blocked — the
  controller may have died post-spawn, pre-persist.
- **Observed**: empty fields could be misread as pre-spawn rejection.
- **Resolution**: explicit durable `spawned:false` written only by code
  paths that provably never invoked spawn; `onSpawn` writes
  `spawned:true`+launcher. Async persist failure is fire-and-tracked,
  never reclassifies the result.
- **Status**: resolved — `missing launch record blocks (unknown, never
  "no spawn")`.

### D3. Dead owner-pid ≠ dead workload
- **Expected**: same-namespace owner death only authorizes an *adoption
  attempt*; the detached porch supervisor may be alive — reconcile the
  exact attempt, adopt observation, never free the slot or relaunch.
- **Resolution**: `adopt_attempt` (structured proof, server-enforced) +
  `reconcileAttempt` binds an existing registry match; `resolve_attempt`
  stays owner-only. Boot-id change is the only env-retirement proof.
- **Status**: resolved — `dead owner + live supervisor: adopt, observe,
  retain slot — no second launch`; `dead owner while launching +
  supervisor appears later: adopt → reconcile → bind`.

## Transport/provisioning (internal-transport.mjs)

### D4. Existing-token path skipped ownership reconcile
- **Expected**: a root-owned token + configured reader uid1001 reconciles
  owner → reader (or fails closed); verify by re-stat.
- **Observed**: `stat.uid===selfUid` short-circuited to ok.
- **Resolution**: chown whenever `stat.uid !== readerUid`; re-stat
  uid/gid/mode after every mutation path; symlink paths refused via
  lstat; chmod/chown failures are never swallowed.
- **Status**: resolved — covered by `u3_crossuid_proof.mjs` (root-owned
  0600 token reconciled, value preserved).

### D5. Token-dir mkdir/lstat errno swallowed
- **Expected**: EACCES/ENOTDIR/EROFS diagnosed; only ENOENT means absent.
- **Observed**: `mkdir{recursive}` catch-all and `lstat().catch(()=>null)`
  collapsed every error to "exists"/"absent".
- **Resolution**: mkdir errors → `token_dir_unwritable`; lstat non-ENOENT
  → `token_stat_failed`.
- **Status**: resolved — `internal token: EACCES/ENOTDIR diagnosed, never
  treated as absent`.

### D6. Internal-client error shape mismatch
- **Observed**: client decoded only a nested `error.{code,message}`
  envelope; the service actually returns flat `{error,code,...details}`
  — `slot_limit`/`revision_conflict` would degrade to `request_failed`.
- **Resolution**: client normalizes the actual service shape, preserving
  status/code/details.
- **Status**: resolved — exercised by every scheduler test through the
  real routed surface.

### D7. Traversal-only token was unreachable
- **Expected**: chowning the token to uid1001 is insufficient if a parent
  dir denies traversal (root-owned 0700 `execution/`).
- **Resolution**: `provisionTraversal` chgrp reader-gid + `g+x` on
  `stateDir` and the token dir, only where not already traversable.
- **Status**: resolved — `u3_crossuid_proof.mjs` `preexisting` fixture
  (root-owned 0700 dir + token, child 1001 reads it).

## Store/domain (execution-store.mjs / execution-domain.mjs)

### D8. JSONL event append corrupted by torn tail
- **Expected**: a partial final line from a mid-write crash is repaired
  before append; no accepted event lost or duplicated.
- **Observed**: blind append concatenated onto a torn tail → both lines
  unparseable → dedup/cursor evidence lost.
- **Resolution**: the jsonl is a canonical atomic projection of
  aggregate-authoritative `run.events`; rebuilds torn/malformed tails,
  dedups seqs within and across batches, counts corruption diagnostics.
- **Status**: resolved — `torn final JSONL line is repaired; accepted
  events keep stable seqs`.

### D9. Ownership was `runnerId`-only (ambient)
- **Expected**: Compose pins `RUNNER_ID=host-runner` — two Node instances
  share it; authority must be per-INSTANCE identity
  (`runnerId`+`instanceId`+pid/starttime+envKey) on every owned mutation.
- **Resolution**: owner-match requires runnerId AND instanceId;
  bind/resolve/heartbeat/adopt/ws-ready/ws-failed/complete_run/
  record_event all owner-gated; deterministic command IDs carry
  `instanceId` so a post-adoption reissue is not a `command_conflict`
  and never impersonates the former owner.
- **Status**: resolved — `foreign instance same env+runnerId`, `adopt_*`
  proof tests.

### D10. Ambient env equality granted workspace authority
- **Observed**: `wsAuthorized` allowed any same-envKey caller (a second
  live Node in the same container) to mark a foreign workspace
  ready/failed or allocate under its reservation.
- **Resolution**: env equality grants nothing; foreign workspaces require
  structured adoption proof against the recorded owner identity.
- **Status**: resolved — `foreign instance … no adopt, no event, no
  mutation`; `adopt_workspace: exact reservation retained`.

### D11. `begin_attempt`/`begin_workspace` were under-strict
- Missing/not-ready workspace accepted; attemptId reusable across
  cards; a second ws could overwrite `run.workspaceId`.
- **Resolution**: existing READY ws + exact canonical cwd required;
  attemptId unique across ALL runs/cards; first ws reservation atomic,
  alternate wsId → 409 unless bound ws is `failed`.
- **Status**: resolved — `begin_attempt requires an existing READY
  workspace + canonical cwd`, `attemptId is globally unique across runs
  and cards`, `one run binds one workspace…`.

### D12. `process_dead` adoption proof accepted bare pid claims
- **Observed**: a payload claiming `observedPid:<live owner>` passed.
- **Resolution**: structured `{pid,starttime,pidNs,finding}` validated
  against the recorded owner identity; only `absent|zombie|recycled`
  pass; lease timeout alone never authorizes.
- **Status**: resolved — `adopt_attempt rejects weak/forged
  process_dead proofs`.

## Service (state-service.mjs)

### D13. Direct run/event/artifact GETs bypassed the repair queue
- **Expected**: recovery BEFORE serving managed state on every read.
- **Observed**: `handleGetRun`/`handleGetRunEvents`/`handleGetArtifact`
  read projections directly — a failed projection could serve
  missing/stale data until an unrelated write repaired it.
- **Resolution**: all three read through `enqueueWrite` (which runs
  `repairState` first); failed repair returns diagnostics, not stale 200.
- **Status**: resolved — `run projection write failure → durable intent
  → restart repair → read`, `run_events projection failure → …`.

### D14. Events route unbounded + torn-line cursor drift
- **Resolution**: canonical seq-sorted read with `limit`/`nextCursor`
  paging and duplicate-free replay.
- **Status**: resolved — `record_event: … cursor paging, canonical read`.

## Scheduler (managed-scheduler.mjs)

### D15. Response envelope misread
- **Observed**: scheduler read `res.workspace`/`res.seq` at top level;
  the service nests them under `result` — workspace data lost, event
  cursor stalled, `ev-run-N` collisions possible.
- **Resolution**: `send()` normalizes to `res.result ?? res` while
  keeping `internalRevision` on the card object.
- **Status**: resolved — `scheduler events land with strictly advancing
  seqs (result.seq envelope)` (3 ticks → seqs 0,1,2 through the real
  envelope).

### D16. Environment retirement auto-relaunched
- **Expected** (parent clarification): proven env loss resolves the
  attempt AND marks the run `interrupted`; no old-PID probing/signaling;
  subsequent ticks never auto-launch — restart policy is U4's explicit
  continue/new-run.
- **Status**: resolved — `environment_lost (bootId change): attempt AND
  run interrupted; no auto-relaunch`.

### D17. Workspace allocation skipped containment/Git-association checks
- `assertInsideRoot` not called; parent symlink could redirect creation;
  existing-path EACCES collapsed to absent; recovered worktrees not
  checked against the registered source repo; source common-dir lookup
  failure silently skipped verification.
- **Resolution**: lexical+realpath containment pre/post-write; `lstat`
  probes distinguish ENOENT from EACCES; `gitCommonDir` fail-closed;
  `verifyWorkspace` enforces `expectCommonDir`.
- **Status**: resolved — `symlinked projectKey parent dir is refused`,
  `source git common-dir failure aborts allocation (fail closed)`.

### D18. Prompt inputs trusted recorded hashes without re-verification
- **Resolution**: `verifyInputs` re-fetches approved requirement/plan
  documents, validates `doc.sha256` AND `sha256(content)` against
  `run.inputs` before workspace allocation/attempt creation.
- **Status**: resolved — `input-hash mismatch refuses launch (immutable
  approved inputs)` (run-projection tamper → mismatch → no attempt, no
  workspace, no launch).

### D19. Blocked state existed only as an event
- **Resolution**: `cmdRecordEvent` persists `run.diagnostic` for
  `launch_blocked`/`workspace_dirty` (type/ts/attemptId/code/detail);
  budget exhaustion completes the run `failed` with reason.
- **Status**: resolved — `attempt budget exhaustion marks the run failed
  durably`, `launcher_unproven` diagnostics throughout.
