Журнал известных отклонений/ограничений U6-модуля. Отчёт:

## Отсрочки по плану (граница U6, не дефекты)

| Отклонение | Статус |
|---|---|
| Браузерная навигация/жизненный цикл (`onMounted`/`onBeforeUnmount`, drawer open/close, tab switching) не доказаны — SSR-тесты покрывают только setup/render скомпилированных SFC. Названия тестов и отчёт явно говорят «setup/render», не «mount». | REQUIRED U7 |
| Живой HTTP-стек: все доказательства listener-free (`svc.request` / injected fetch). Совместимость через реальный listener+Compose-раннер — U7. | REQUIRED U7 |

## Принятые решения U6

- **Per-field delta persistence.** `updateCard` помечает только реально
  изменённые поля; merge для CAS идёт от remote-строки. Полный stale-draft
  от CardDrawer НЕ перезаписывает соседние поля — drawer шлёт только
  отредактированные относительно baseline загрузки.
- **Same-card projection refresh.** Watcher на `deps.card` обновляет все
  серверные managed-поля (stage/status/project/blocked/blockedReason/
  cancelled/session/sessionKey) при неизменном `cardId`; пользовательские
  поля (title/description/agent/priority/acceptance/verification/links)
  сохраняются; обновление никогда не помечает dirty и не планирует save.
- **Single-flight semantics.** `refreshCard` — один flight на карточку;
  `refreshRun` — токен на (selection,generation,request) — старый A→B→A
  ответ не гасит новый flight и не применяется. Event-drain идёт
  страницами внутри одного flight; `eventsPending` остаётся true при
  отказе страницы — терминальный run добирает историю ретраями, а не
  теряет её.
- **Command discipline.** Каждый `sendCommand` держит busy-флаг, делает
  свежий read и шлёт live `expectedControlRevision` (enable — без rev,
  domain допускает optional-or-0). Net-stamp ставится ДО POST — поздний
  отказ команды не переводит уже здоровое состояние в offline.
- **RemoteKVStore poll-таймер.** В браузере интервал живёт намеренно всю
  сессию; в node-харнессе освобождается через `__resetWebKvForTests`
  (dispose + probe reset). Не `unref` — скрытие реальной работы таймера
  запрещено.
- **Fail-closed fetch isolation.** `globalThis.fetch` в тестах —
  детерминированный роутер, установленный ДО всех store-сьютов;
  неизвестный маршрут = throw. С `{svc}`-делегатом legacy `/api/state/*`
  идёт через реальный сервисный handler (настоящие rev-семантики).

## Семантические ограничения (поведение, не баг)

- Lifecycle-мутации managed-карточек (move/status/flag/delete/drag)
  отказывают с правдивой причиной — managed-поля меняются только через
  execution API.
- Удалённые remote-карты не воскрешаются: adoptRemoteBoard удерживает
  только явно новые/unsaved локальные строки.
- `porchRunId` никогда не интерпретируется как ACP session id; managed и
  porch секции в Workflow раздельны.
- SSR-ассёрты опираются на текстовую разметку — это доказательство
  render-выхода, не интерактивного поведения.
