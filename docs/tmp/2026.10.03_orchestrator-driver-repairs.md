# Orchestrator driver seam repairs — 2026-10-03

Scope: controller/prompt only, plus focused deterministic regression tests. No shared domain, storage, environment controller, deployment, or live model changes.

Completed repairs:

- The assembler builds without a task binding. Worker settlement supplies the actual authenticated run identity, reads the domain's `resultCandidate.commit`, and selects the latest completed work/fix attempt. A retained returned candidate cannot suppress a new fix settlement.
- Fix attempts use a distinct attempt identifier and an immutable registered snapshot of the candidate canonical, including its exact project root, SHA and snapshot ID. They do not mix immutable snapshot seeding with mutable `fromCanonical`. Snapshot generations advance with durable used-budget counters.
- Historical terminal worker namespaces must positively settle before subsequent launch, import, or run completion. Missing worker registry records do not count as physical disappearance. Long internal command IDs receive deterministic bounded hashes.
- Dependency bases publish fsynced immutable receipts with exact run/task/source/base/ancestor ordering, commits, dependency edges and patch hashes. Retries validate the repository's private isolation, path, clean status, HEAD and tree. Concurrent creators publish with an exclusive hard-link operation and reuse the same winner. Crash-before-publication and losing builds can leave private unreferenced repositories; they never become a launch basis, and automated garbage collection is outside this repair.
- Assemblers explicitly declare `additionalPaths` and `resolvedPaths` in one JSON result. The driver commits those declarations before import, replays committed bytes during recovery, and forwards both lists to storage without deriving permissions from the resultant diff. Malformed, multiple, duplicate, overlapping or unsafe declarations fail closed.
