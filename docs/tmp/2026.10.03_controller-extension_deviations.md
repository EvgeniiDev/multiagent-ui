# Controller extensions — 2026-10-03

The trusted controller now provides physical worker barriers, isolated writable scratch, immutable snapshots of current Swarm canonical code, and approved dependency preparation from canonical HEAD.

## RPC and runtime contract

`worker.freeze({workerId})` and `worker.thaw({workerId})` target only the container ID in the registered worker record. They persist intent before Docker pause/unpause and verify the resulting inspect state before returning success. Freeze is idempotent when paused. The paused state remains a live namespace (`namespaceAlive:true`) and reports `frozen:true`. Startup reapplies outstanding freeze intent to running workers. Failed or unknown inspections never grant a barrier. Stop intent is durable before effects and blocks all later thaw calls. A confirmed paused worker is force-removed to stop it without resuming cancelled work; other stop paths also require explicit terminal/absence proof.

`worker.prepare` accepts `materials.scratch:{id:<safeId>,mount:'/work/scratch'}`. It rejects other keys, mount targets, unsafe IDs, directory symlink redirects, and changed bindings on repeated preparation. Each scratch source is exactly `workers/<workerId>/scratch`; its writable mount does not change the role's project mount mode. Scratch metadata is durable in the worker registry.

`swarm.snapshot({canonicalId,workspacePath?,generation})` requires a registered ready canonical, a nonnegative integer generation, and an optional workspace path equal to the registered controller worktree or its host view. The broker must use that canonical binding rather than an unrelated Core workspace. All registered Swarm participants for the canonical must have inspected paused/stopped/gone evidence before snapshot admission. Fixed Git staging and commit commands capture tracked modifications, new nonignored files, deletions, and executable modes. Hooks and signing are disabled for the controller-created commit. An isolated bare clone pins the resulting code after later imports or edits. The durable generation binds exact tree bytes; reusing it for another tree is refused.

Snapshot return fields are `{ok,canonicalId,generation,snapshotSha,treeSha,materials:{projectRoot,snapshotSha,snapshotId}}`. The runtime must preserve `materials.snapshotId`; the controller resolves that ID to its own immutable source and refuses mismatched source/hash fields. Role workers retain their declared snapshot-ro project mounts. Existing archive restrictions on unsafe symlink targets still apply.

`deps.prepare({setupId,canonicalId})` resolves the registered canonical's clean committed HEAD. Optional projectRoot/snapshotSha must match the canonical binding. Dirty canonical code must first be snapshotted explicitly. The original pinned-project form remains available. Only registered setup IDs and binding fields are accepted; clients cannot supply setup argv. Existing approved setup-worker execution, lockfile hash, dependency-set identity, and failure behavior remain intact. Returns include `snapshotSha` and `canonicalId` alongside the existing setupId/depSetId/lockHash/cached fields.

The Docker API implementation lives at `deploy/execution/docker-api.mjs`; the initially requested server-side path does not exist. Parent approved using the imported deployment module. The controller client exposes `workerFreeze`, `workerThaw`, and `swarmSnapshot`; runtime wrappers and mode-driver integration are separate author-owned work.
