## Контекст входа

- Предыдущая сессия: codex api-flow exit 1. Честная причина доказана:
  porch пишет `meta.child_pid` вторым meta-update ПОСЛЕ `adapter.start()`;
  status-read внутри этого окна сообщал child_pid absent → record-once
  защёлкивал `childPid: null` навсегда → `terminalProof` →
  `child_unproven`/`terminal_unproven` на каждом тикe, run stranded
  `active/implement` (run `run_6497b779-e29f-4b50-8cc1-4f04391639c6`,
  attempt `att-…-1`, porch `run_wild-kestrel-4a83`, диагностика записана
  1790845396890).
- Фикс (уже в дереве, `server/execution/managed-scheduler.mjs`):
  fill-once ветка `childFillable()` — NON-terminal status, supervisor
  pid+starttime+pidNs идентичны записи → child identity дозаписывается
  через `observe_attempt` («recorded while live», та же сила привязки).
  Terminal-time disclosure остаётся unproven; childNone и записанный
  childPid не трогаются. Регрессии: 2 новых теста в u4_core_selftest,
  61/61 green (перепроверено этой сессией, `node scripts/u4_core_selftest.mjs`
  → pass 61 fail 0, 15.06s).
- Self-run-id этой сессии: `run_noble-island-0011` (devin, активный
  porch delegate — единственный).
