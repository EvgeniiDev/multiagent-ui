# Browser acceptance deviations — 2026-10-03 (harness authoring, NO live run)

Scope: new harness `scripts/acceptance_modes_browser.py` + contract
`.agent-tmp/browser-acceptance-contract.md`. No execution, no deploy, no prod
writes, no UI changes in this task.

## D1 — profiles have no server registry; runtime discovery required

Backend contract (§3: `start` takes FULL inline `AgentProfile` objects; "the UI
uses the same profile source it already uses for fusion composition") defines
no profile-registry endpoint. The UI's only server-blessed source is
`exec.compatibility[cli].models` (ExecutionPanel: `fusionModels`, `orchProfiles`
both read `compatibility?.pi?.models`).

Harness decision: never hardcode model IDs; order is explicit `--profile-*`
args → UI-rendered compat list → fail closed `profile_registry_missing`.
Parent run must supply live profile IDs (prod runner egress-gated, same as
F4's zen-relay free pair) or confirm the compat list is populated in prod.

## D2 — card selection in the UI is a TODO for the parent run

The harness opens the board URL and asserts the execution/prep panel renders,
but the exact board→card-open affordance (card picker testids) was not
pinned without a live DOM. Marked `TODO(parent-run)` at the mode entry;
parent fills the selector against the deployed UI before executing.

## D3 — orchestrator/fusion start selectors fall back to `exec-start`

Contract UIs verified in source: `orch-start` is NOT a real testid (orchestrator
composition lives under the shared start row); `swarm-start` IS real;
`exec-start`/`exec-accept` are real. The harness tries the mode-specific
selector, falls back to `exec-start`, and fails closed if neither exists.

## D4 — preparation doc-attach flow simplified vs e2e_preparation.py phases

The isolated P5 suite covers stale/gates/legacy/restart phases against the U7
overlay; this harness covers only the acceptance path (grill answer → docs →
gates → ready) because prod has no overlay controls. Stale-409, offline, and
restart behaviors are NOT re-proven here.

## D5 — per-mode budget floor 600s; grill question wait 300s inside it

Task requires ≥600s per mode; the grill-discussion wait consumes up to 300s of
the preparation budget. Model turns are real — a slow provider can exhaust the
floor; parent may raise `--timeout-s` but never lower it.
