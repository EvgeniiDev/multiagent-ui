## Design decisions recorded up front (not deviations)

- Private repos are seeded via `git archive <baseCommit> | tar -x` into a
  fresh `git init` repo — never clone/fetch — so no foreign ref or object
  can leak in. Isolation verified at creation (`verifyPrivateRepo`) and
  re-verifiable later; negative proof via `assertForeignUnresolvable`.
- Each worker result carries ONLY its own diff (`exportWorkerDiff`
  `inputCommit..HEAD`); dependency snapshots re-apply parent patches in
  stable topo order, so the ancestor content arrives without the ancestor
  commits. A diamond ancestor is therefore applied exactly once.
- Conflict detection is `git apply --check` BEFORE any worker launches
  (`snapshot_conflict`, half-built repo removed). Resolution text is
  caller-supplied; the module verifies content presence (each parent's
  changed paths in the resolution tree), not commit ancestry — private
  repos mint disjoint commit ids by construction, so cross-repo
  `merge-base --is-ancestor` can never hold.
- `freezeResult` uses `git add -A` (full actual state: dirty tracked,
  untracked new, deletions, mode changes) and is idempotent on a clean
  tree. `resultHash` binds the full report (content tree + commits +
  provenance) and is the acceptance binding the backend publishes as
  `resultSha256` (aligned with `.agent-tmp/backend-ui-contract.md` §4).
- Integration artifacts are durably idempotent (atomic write, never
  mutated; same key + different content refuses) with manifest-shape
  validation on load (`artifact_corrupt`).

## Deviations

### D1 — topo tie-break differs from the test's first guess

- **Expected:** `transitivePredecessors` for the diamond fixture would yield
  `['a','b','c']` (matching declaration order of b before c).
- **Observed:** the O1 `topoOrder` (Kahn, declaration-ordered queue over the
  fixture `[d,c,a,b]`) yields `['a','c','b']`. Evidence:
  `node --test scripts/test_orchestrator_workspaces.mjs` —
  `actual: ['a','c','b'], expected: ['a','b','c']`.
- **Action:** fixed the TEST to assert the true deterministic order
  (`['a','c','b']`) plus the invariant that matters (diamond ancestor `a`
  exactly once, `git log` shows base + 3 parent commits). The module reuses
  O1's `topoOrder` unchanged — no fork of the ordering algorithm.
- **Resolution:** resolved. Remaining risk: none — order is deterministic
  for a given declaration; the backend must persist the declaration order
  it decomposes with.

### D2 — cross-repo ancestry check unimplementable for resolutions

- **Expected:** `recordResolution` would prove each input contained via
  `merge-base --is-ancestor` against the resolution HEAD.
- **Observed:** private repos are autonomous stores (`git archive`-seeded);
  a parent's resultCommit never exists as an object in the resolution repo,
  so the ancestry probe always fails. Evidence: test failure
  `resolution_incomplete ... a side was discarded` on a resolution that
  provably contained both sides' files.
- **Action:** replaced ancestry proof with content proof — the caller
  supplies each parent's `changed[]` (from its own `exportWorkerDiff`) and
  the module requires every changed path present in the resolution tree
  (`resolution_incomplete` otherwise). Rationale recorded in the module
  header.
- **Resolution:** resolved. Remaining risk: a resolution could contain the
  right paths with gutted content and still pass — content-semantics review
  stays with the integrator/verifier participant, as KTD3 requires (module
  never invents approvals).

## Repair pass R9c345b5 + final review (2026-10-03/04)

Actual probes (real git temp trees in `scripts/test_o2_repair_probes.mjs`,
12 tests, all watched RED before the fix) reproduced 8 blockers plus 5
final-review findings. Root causes and fixes:

### R-B1 — unchanged base accepted as resolution (path existence insufficient)
- **Expected:** a resolution must carry each side's CHANGED CONTENT.
- **Observed:** `recordResolution` required only that each parent's changed
  PATHS exist in the resolution tree — a pristine base passed.
- **Action:** op-aware per-file content proof. Parent diffs now carry
  `files[]` (new `exportWorkerDiff` field from `diffFileEntries`: op,
  before/after blob-byte hashes, modes, binary). Uncontested
  add/modify/modechange requires exact parent bytes (base bytes rejected);
  deletion requires absence; same-path-different-bytes is a true conflict
  requiring `resolvedPaths[]` with a hand-merge differing from every side.
  `changed[]`-only parentDiffs entries are rejected (existence proves nothing).

### R-B2 — legitimate parent deletion rejected
- **Observed:** missing path unconditionally threw `resolution_incomplete`.
- **Action:** uncontested deletion (parent op deleted, path absent) is
  ACCEPTED. Delete-vs-change conflicts still require `resolvedPaths`.

### R-B3 — parallel conflicting recordResolution: last writer won
- **Observed:** read-check-then-`atomicWriteFile`-rename overwrote the
  canonical artifact; both racers succeeded.
- **Action:** O2-owned `server/execution/orchestrator/durable-artifact.mjs`
  `exclusiveCreateArtifact`: full record → temp file + fsync, then
  `fs.link(temp, final)` (atomic exclusive publish — exactly one racer
  wins, final path never partial), dir fsync, unlink temp. Loser re-reads
  the canonical winner: identical → idempotent return, else
  `artifact_mismatch`. Shared `server/execution/common.mjs` deliberately
  UNTOUCHED (scoped blast radius; no `file_exists` in shared vocabulary).

### R-B4/R5 — checkCompatible superset+different-baseTree bypass
- **Observed:** extending-input-set + differing baseTree silently bypassed
  the same-resolution requirement.
- **Action:** bypass REMOVED. Shared inputs must agree on commits AND
  resolution identity; the only bypass is explicit proven preservation —
  the superseding side lists the other's key in `supersedes[]` (a recorded
  joint resolution). Conservative reject otherwise.

### R-B5 — empty own diff dependency rejected
- **Observed:** empty `formatPatch` threw `invalid_argument`.
- **Action:** empty patch = accepted no-op (one `--allow-empty` parent
  commit + provenance entry, order/parents exact).

### R-B6 — binary exported diff non-replayable
- **Observed:** `git diff --full-index` emits a `Binary files differ` stub.
- **Action:** `exportWorkerDiff` uses `git diff --binary --full-index`;
  `assembleDependencySnapshot` replays via `git apply` (binary-safe).

### R-B7 — freeze accepted nonexistent inputCommit; thin change report
- **Observed:** no input validation before `add -A` (nonexistent sha +
  empty diff froze fine); report listed names only.
- **Action:** inputCommit must resolve AND be an ancestor of HEAD BEFORE any
  staging (else `commit_invalid`/`diff_not_ancestor`, repo untouched).
  Report gains `fileDetails[]` = {path, op, modeBefore, modeAfter, binary}.

### R-B8 — removed parent passed provenance
- **Observed:** only listed parents were compared; set changes passed.
- **Action:** full-set equality — removed OR added parent ⇒ `stale_input`.

### R-R1 — resultHash unstable across identical re-freezes
- **Observed:** hash covered `dirtyPaths` (transient status output) + note.
- **Action:** `resultHash` over STABLE fields only
  (version/kind/taskId/inputCommit/resultCommit/generation/parentCommits/
  changed/fileDetails/treeHash). Old hashes are NOT comparable — recompute.

### R-R2 — shared writer upgraded without review (scope)
- **Observed:** first repair attempt added `durableWriteFile` /
  `exclusiveCreateFile` to shared `common.mjs` and rerouted
  `atomicWriteFile` through fsync for ALL callers.
- **Action:** reverted (`git checkout -- server/execution/common.mjs`,
  verified zero diff); durable exclusive writer lives in O2-owned
  `orchestrator/durable-artifact.mjs`. No rationale published for a shared
  upgrade — default local helper stands.

### R-R3/R4 — corrupt artifact treated as absent; weak validation
- **Observed:** any read/parse failure → `null` (rewriteable); keys/types
  unchecked.
- **Action:** ONLY ENOENT is absence; every other failure throws
  `artifact_corrupt` (fail closed, incl. second-publisher path).
  `validateArtifact` checks all keys, version/kind, input/order types, sha
  shapes, and recomputed `artifactKey(record.inputs, record.order)` ===
  filename key.

### Resolution provenance follow-up

Nine real Git regressions cover actual empty committed parent ranges, modified
and added executable modes, arbitrary/stripped/forged-empty file proofs, omitted
or mutated untouched base files, explicit assembler-only edits, valid sequential
supersession, and a forged dependency declaration without preserved input bytes.
The first six failed against dfe9e2b before implementation and pass after repair.

recordResolution now rederives full parent files from the declared actual
input/result commits in each exported repo. No caller-side proof filtering or
no-op omission is accepted. baseCommit resolves in the result repo and binds
baseTree; complete base/result changed inventory protects all remaining paths.
additionalPaths explicitly authorizes assembler-only mutations. All parent
proofs bind after bytes and mode; dependencies justify supersession only when
the later real input tree preserves earlier result bytes and mode. Artifacts
version2 retain these proofs, baseCommit, dependency graph and additionalPaths.
Version1 records fail closed. Existing storage test callers forward full exports.

A bounded marker-only fixture also confirmed freezeResult invokes a
worker-controlled pre-commit hook. Parent owns separate safe Git isolation
repair; this content-proof commit does not claim that independent issue fixed.
