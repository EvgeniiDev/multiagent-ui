# U1 deviation journal — 2026-09-30

Every unexpected observation/deviation found during U1 implementation and
review, with evidence, resolution, and remaining risk. No secrets.

## Runtime defects (found by independent review, fixed)

### D1. `spawnBounded` could wait forever on inherited pipes
- **Evidence**: `spawnBounded` resolved only on `close`. A direct child
  spawning a descendant that inherits stdout/stderr keeps the pipes open
  after the child dies; repro returned after 660ms with timeout 50ms /
  killGrace 20ms, and would hang indefinitely for a long-lived descendant.
- **Resolution**: settle on `exit` + bounded `settleGraceMs` drain window;
  the runtime destroys stdio pipes and marks `observationCut: true` when
  the settle deadline cuts observation. Descendant processes are not
  signalled (porch supervisors must survive).
- **Risk**: none known; regression fixture covers inherited pipes.

### D2. Killed child always burned the full settle grace
- **Evidence**: timeout fixture took 2154ms ≈ timeout 150ms + default
  `settleGraceMs` 2000 — i.e. `close` did not fire promptly after the
  killed child's `exit`, so resolution always waited the whole settle
  deadline. Root cause of the lagging `close` is inferred (lingering
  stdio pipe handles, most plausibly the still-open stdin side); the
  demonstrated pipe-holding defect itself is D1 (inherited stdout/stderr).
- **Resolution**: destroy `child.stdin` on `exit` (observed to restore
  prompt `close` settlement) and keep the bounded settle fallback; stdin
  `error`/EPIPE is handled on the input path.

### D3. `start()` failed on a fresh execution root
- **Evidence**: ENOENT — `mkdir(attemptDir)` ran before `attemptsDir`
  (and `rootDir`) existed. Reproduced with `rootDir=<mkdtemp>/execution`.
- **Resolution**: `mkdir -p` parents explicitly first; attempt dir is still
  created exclusively (`EEXIST` → `attempt_exists`).

### D4. `reconcile` used OR semantics
- **Evidence**: passing unique `artifactsDir` + `cwd` could attach an
  unrelated historical attempt sharing the same cwd.
- **Resolution**: all supplied selectors must match (AND). Regression test:
  an older run in the same cwd with different artifactsDir is excluded.

### D5. `environment()` lacked pid-namespace and start-time identity
- **Evidence**: `bootId`+`hostname` cannot distinguish a restarted
  container (stable hostname, same host boot, recreated pid ns).
- **Resolution**: record `/proc/self/ns/pid`, uid/gid, node pid and
  `/proc/self/stat` starttime, plus per-run supervisor `process`
  `{pid,starttime,pidNs}` in status results. PIDs alone are never treated
  as proof of ownership.

### D6. Post-launch persistence failure could mask a live launch
- **Evidence**: an early draft risked a `launch.json` write failure after
  porch returned a valid run id degrading the attempt to
  `launch_failed` — implying safe-to-retry while a detached supervisor
  existed.
- **Resolution / actual contract**: phase classification is decided by the
  handshake alone and is never downgraded afterward. A validated run id
  always returns `phase: 'launched'` + `porchRunId`; a persist failure is
  reported separately as `recordPersisted: false` with `persistError` in
  the record. `launch_uncertain` is reserved for unconfirmed identity
  (handshake timeout, signal, or exit 0 without a run id) — those are
  never silently retried either; `reconcile` by attempt selectors is the
  resolution path.

### D7. `configPath` was a mutable external pointer
- **Resolution**: porch config is snapshotted — serialized into
  `attemptDir/porch-config.json` per attempt; `start` requires an explicit
  `config`/`configPath` snapshot (refuses to borrow installed config).

### D8. `params.env` could reintroduce dropped vars
- **Resolution**: extras pass through the same filter; `PORCH_*` routing
  keys and model overrides (`CODEX_MODEL`, `DEVIN_MODEL`, `PI_MODEL`, …)
  cannot be smuggled back. Dropped keys are reported in the launch record.

### D9. pi session id collision across attempts
- **Evidence**: pi adapter defaults session id to the artifacts dir
  basename — always `artifacts` — so two attempts in one cwd share a pi
  session.
- **Resolution**: runtime sets `PORCH_PI_SESSION_ID=acp-<attemptId>` in the
  launch env (runtime owns `PORCH_*`).

## Fake backend defects (fixed)

### D10. Pending outcome overrode cancellation
- **Evidence**: `start` → `cancel` → after the scheduled `delayMs` the run
  flipped to `completed` (repro: default 5ms outcome, delay 20, status).
- **Resolution**: `setStatus` clears the pending outcome timer and terminal
  state is immutable.

### D11. `fake.wait` used unref'd poll timers only
- **Evidence**: a top-level awaited `fake.wait` could let Node exit with
  the promise unresolved.
- **Resolution**: poll timers are ref'd and per-poll waiter callbacks are
  cleaned up.

### D12. Fake was weaker than the real backend
- **Resolution**: exclusive attempt ids (`attempt_exists`), mandatory
  explicit `config`/`configPath`, absolute cwd, prompt validation — same
  invariants, so the fake cannot hide U3 controller mistakes.

## Smoke-driver corrections (fixed before live calls)

### D13. `skillRoot` off-by-one
- `path.resolve(dirname(porch),'..','..')` resolved to `.../skills`, not
  the skill root; fixed to one level up from `scripts/`.

### D14. No cleanup on failed/expired observation
- `fail()`/`process.exit` could leave a live supervisor. Now all exits run
  bounded cleanup (cancel + `wait` ≤45s) for OUR run id only; a
  `launch_uncertain` outcome reconciles strictly by this attempt's
  selectors and cancels only matched runs.

### D15. Pass criterion too weak
- PASS now requires terminal `completed` AND the expected
  `U1-SMOKE-OK-<AGENT>` marker in the full `wait` result.
- Already-terminal-before-cancel is reported as evidence, never a pass.

## Environment/test observations

### D16. Fixture timeout bound was unrealistic
- Assertion `<2000ms` ignored default `settleGraceMs: 2000`. Fixture now
  uses explicit small values (150/200/250ms) and asserts <1200ms.

### D17. Typed errors asserted via message text
- `RuntimeError` carries `code`; tests assert `e.code` instead of
  `/regex/` on the message.

### D18. Control stub arg shape
- Stub received `delegate` as `$1`; now consumes the subcommand prefix
  before dispatch. Unused stub code removed.

### D19. `ps`/`pkill` absent in `node:22-slim`
- Checked porch sources: no `ps`/`pkill`/`pgrep` execution (Python reads
  `/proc` directly). `flock`, `setsid`, `nohup`, `timeout`, `stdbuf`
  present. No package added.

### D20. `node` inside container resolves to mounted host binary
- `PATH` puts `/home/hermes/.local/bin` first → node v26.7.0 (host), not
  the image's `/usr/local/bin/node` v22.x. Recorded; selftest executed
  under BOTH and passes 19/19 each.

### D21. `bash -c` exec optimization made observer pid 1
- In `bash -c 'a && b'` bash execs the last command, so the fresh observer
  process ran as pid 1 (launcher was pid 7, exited first). Restart proof
  stands: distinct node processes, sequential in one container.

### D22. Reused smoke workspace shows `git:false`
- Second smoke in the same ws found an existing repo; `git commit` had
  nothing to commit → emitted `git:false` though git works. Cosmetic label;
  repo init is non-fatal by design.

### D23. Restart-gate PASS criterion too loose
- **Evidence**: `PASS` accepted any terminal status seen by the fresh
  observer (`w.status==='cancelled' || st.terminal`), so a run that failed
  or finished on its own could masquerade as restart recovery. Also
  `process.exit` inside `try` bypassed the `finally` cleanup.
- **Resolution**: PASS now requires the full chain — distinct
  launcher/observer processes, same recorded `pidNs` + uid, the exact run
  LIVE at observe time, `cancel` requested, then `wait` → terminal
  `cancelled`. Already-terminal runs emit a labeled `terminal_history`
  datapoint. Early exits return through `finally`, which cancels + waits
  (≤45s) on our own run id only.
- **Result**: the strict driver was rerun with `run_solar-delta-0165`: live run rediscovered, cancel requested, terminal `cancelled` / 130. Independent controller rerun: `run_crisp-cobalt-3fa6`, distinct Node processes, same UID/pidNs, live run observed and cancelled / 130.

## Remaining risks / notes

- Observation caps (exact): `wait` stdout is capped by `maxResultBytes`
  (default 8 MiB — sized to carry the full final text); `status`/`events`/
  `cancel`/`list` stdout by `maxControlBytes` (default 1 MiB); launch
  handshake stderr tail by `LAUNCH_MAX_BYTES` (256 KiB). A capped payload
  fails JSON parsing and surfaces as an error result (`wait` →
  `outcome:'error'`, `error.code:'parse_error'` or classified CLI error);
  truncation is never returned as silent data. `observationCut` is a
  separate launch-diagnostics flag marking that the bounded settle window
  cut observation of the handshake process, unrelated to payload size.
- Worktrees are operational context, not a security boundary — the runtime
  never treats them as sandboxing.
- Cancel verified per CLI (distinct abort paths — Devin ACP interrupt,
  Codex app-server, Pi RPC): `run_scarlet-comet-a92e` (pi, 8s),
  `run_lively-cedar-e1d3` (codex, 12s), `run_warm-lichen-89c9` (devin, 9s),
  plus `run_ruby-birch-1d7e` (pi, via restart proof). All reached terminal
  `cancelled` (exit 130). Developer registries show 8 smoke runs, all terminal; the independent controller restart run is also terminal.
