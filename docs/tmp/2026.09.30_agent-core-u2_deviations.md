## Storage layer (execution-store.mjs)

### D1. Corrupt aggregate treated as "absent" (fail-open)
- **Expected**: a corrupted existing managed-card aggregate must fail
  closed (`corrupt_store`); the card stays managed — cannot be deleted,
  re-enabled, or silently unmanaged.
- **Observed**: `loadAggregate` returned `null` on malformed JSON and on
  `cardId` mismatch, identical to a missing file.
- **Evidence**: parent source review; original implementation's catch-all
  returned null.
- **Resolution**: `ENOENT` returns `null`; every other read/parse/shape
  failure throws `RuntimeError('corrupt_store')`. `listManagedCardIds`
  stays directory-driven so the corrupt file keeps the card managed.
- **Status**: resolved — `corrupt aggregate fails closed everywhere but
  stays managed` self-test.

### D2. Corrupt preset registry silently became empty
- **Expected**: existing `presets.json` with malformed JSON/shape →
  `corrupt_store`; never overwritten with an empty registry.
- **Observed**: `loadPresets` returned `{version:1,presets:[]}` on parse
  or shape failure, and the save path could persist that empty registry.
- **Resolution**: only `ENOENT` yields the valid empty registry;
  malformed existing files throw `corrupt_store`.
- **Status**: resolved — `corrupt presets registry fails closed and is
  never overwritten`.

### D3. Blob reuse/read trusted the filename, not the content
- **Expected**: content-addressed blobs are verified by hashing actual
  UTF-8 contents on reuse and on read; approval/serving calls
  `requireBlob` which rejects missing or corrupt evidence.
- **Observed**: `writeBlob` reused an existing file after `stat().isFile()`
  only; `readBlob` returned arbitrary bytes.
- **Resolution**: `writeBlob` reads and rehashes an existing blob before
  reuse (mismatch → `corrupt_store`); `readBlob` verifies content against
  the requested SHA-256; `requireBlob` rejects missing/corrupt references;
  approval and document-serving go through it.
- **Status**: resolved — `blob evidence: reuse verifies hash;
  missing/corrupt blocks approval+serve`.

## Domain layer (execution-domain.mjs)

### D4. `computeProjection` threw `ReferenceError: run is not defined`
- **Expected**: projection reads run state strictly from the aggregate.
- **Observed**: a `run` identifier only existed inside the `lifecycleStage`
  closure. Parent reproduced with a direct import, minimal aggregate+row.
- **Resolution**: projection rewritten to resolve the run via
  `aggregate.runs`/`aggregate.currentRunId` explicitly.
- **Status**: resolved — `computeProjection: no unbound run reference;
  run status maps stage`.

### D5. `statusByStage` rebuilt from the incoming row
- **Expected**: protected status history evolves only from authoritative
  aggregate projection history; legitimate transitions record the *prior*
  authoritative stage/status.
- **Observed**: `computeProjection` rebuilt `statusByStage` from the
  incoming board row; parent reproduced forged history
  `{spec:'done',reviewtest:'accepted'}` overwriting authoritative
  `{spec:'in_progress'}`.
- **Resolution**: `statusByStage` starts from
  `aggregate.projection.statusByStage`; a stage transition records the
  previous authoritative pair. Enable snapshots the card's pre-managed
  history exactly once (legitimate handoff); afterwards history only
  evolves through projections.
- **Status**: resolved — `projection history: statusByStage comes from
  the aggregate, not the row`.

### D6. Duplicate managed card ids in incoming board writes
- **Expected**: duplicate managed card ids rejected
  (`duplicate_card_id`) or safely canonicalized.
- **Observed**: `mergeBoardWrite` overlaid only the Map-selected row; a
  second row with the same managed id stayed unprotected and could carry
  forged stage/claim-facing fields.
- **Resolution**: `mergeBoardWrite` rejects duplicated managed ids with
  409 `duplicate_card_id`; `repairBoardProjections` canonicalizes
  pre-existing duplicates (first row kept).
- **Status**: resolved — `board PUT: managed fields restored, forged
  markers stripped, deletion refused`.

### D7. commandId dedup evicted outcomes after 256 commands
- **Expected**: dedup outcomes persist forever — replay after >256 later
  commands returns the original outcome; changed payload conflicts.
- **Observed**: `recordCommand` had a capacity eviction.
- **Resolution**: dedup records live in the aggregate `commands` map,
  persisted atomically with the command outcome, no eviction horizon.
  Dedup lookup precedes `expectedControlRevision` validation.
- **Status**: resolved — `dedup: no eviction horizon — >256 later
  commands, replay still returns original`.

### D8. Plan versions had no requirements-version binding
- **Expected**: a plan version records the requirements versionId/hash it
  was prepared against; reqA→planA→reqB then approving reqB+planA must
  not silently assert planA was made for B.
- **Observed**: `attach_document` stored no binding; approval used
  "currently approved requirements".
- **Resolution**: `attach_document` (kind `plan`) requires
  `payload.requirementsVersionId` (optional hash also bound); approval
  verifies the plan's bound requirements version equals the currently
  approved requirements version.
- **Status**: resolved — `plan is bound to the requirements version it
  was prepared for`.

### D9. Approval allowed implicit "approve current version"
- **Expected**: approval payload carries explicit `versionId` and
  `sha256`; supplied hash must match the immutable blob and the stored
  version record.
- **Observed**: omitted versionId/hash approved the current version; hash
  was not verified against the blob.
- **Resolution**: `approve_plan` requires explicit `versionId`+`sha256`;
  `requireBlob` verifies blob integrity first, then the version record is
  compared. Requirements approval follows the same explicit-binding rule.
- **Status**: resolved — `approvals require explicit versionId+sha256;
  stale versions rejected`.

### D10. CLI compatibility treated effort/params as unconditional globals
- **Expected**: per-CLI/model validation of supported settings; unknown
  fields rejected before start. Devin encodes effort in the model id and
  must reject standalone effort/params.
- **Observed**: `effort` and `params` accepted globally for any CLI.
- **Resolution**: the compat table declares `supportedSettings` per
  CLI/model; unknown fields fail validation; Pi/Codex supported
  combinations keep their explicit settings.
- **Status**: resolved — `presets CRUD + per-CLI compatibility
  (effort/params are not global)`.

### D11. Enable checked only `leaseUntil`, then erased expired evidence
- **Expected**: card-scoped gate — a live same-card claim refuses;
  expired claims carrying pid/runnerPid/sessionId or similar identity
  evidence are ambiguous → fail closed, evidence preserved; only
  evidence-free expired markers purge automatically; `claims.attempts`
  optional. No `/proc` inference (separate pid namespaces, PID reuse).
- **Observed**: expired lease → claim+attempt deleted; earlier code
  probed `/proc/<pid>/cmdline` to infer runner identity — proves nothing
  across containers/namespaces (KTD4); `attempts` access could TypeError.
- **Resolution**: `/proc` probing removed entirely. Classification:
  live lease → `active` (409 `legacy_claim_active`); expired with any
  execution-identity evidence → `ambiguous` (409
  `legacy_claim_unresolved`, record preserved); expired evidence-free
  marker → `stale` (purgeable). Terminal state requires explicit operator
  reconciliation (`boardctl release`) or the owning runner's own sweep.
  `attempts` guarded.
- **Status**: resolved — `enable: live claim and evidence-bearing
  expired claims refuse`.

### D12. Corrupt compat override silently fell back to seed/cache
- **Expected**: malformed operator `cli-compat.json` → `compat_invalid`
  diagnostic; unsupported model/settings must never become accepted under
  a stale table.
- **Observed**: `loadCompatOverride` swallowed errors and returned null,
  leaving the previous table active.
- **Resolution**: strict validation — malformed JSON/shape/unknown keys →
  `compat_invalid`; `mergedCompat` rejects unknown CLI names; preset
  validation fails closed when the override is invalid.
- **Status**: resolved — `compat override: valid extends, malformed
  fails closed`.

## Service layer (state-service.mjs)

### D13. Aggregate outcome persisted before external writes — replay lied after crash
- **Expected**: durable pending-write intents recorded before the
  aggregate commit lands; recovery drains intents before reads, commands,
  and legacy writes; preset recovery never overwrites a newer registry
  entry; `save_preset` binds a full composition snapshot to the card.
- **Observed**: `saveAggregate` committed the command outcome while the
  preset registry write could still fail; replay then returned success
  with a missing registry entry. Card composition was not snapshotted, so
  registry edits/deletion altered the card's selection.
- **Resolution**: aggregates carry `pendingWrites` (semantic intents:
  `board_projection`, `claims_purge`, `preset_upsert`) persisted with the
  aggregate before external effects flush; `repairState` drains them
  idempotently (preset upsert skips newer registry entries) inside the
  serialized queue before every op and before managed reads;
  `save_preset` attaches the validated composition snapshot to the card.
- **Status**: resolved — injected-fault tests `crash: enable committed
  but claims purge failed — restart drains intent`, `crash: save_preset
  registry write failed — restart drains; newer registry wins`, `crash:
  attach committed but board projection failed — restart repairs`,
  `crash: aggregate write failure — command not recorded, retry is
  clean`.

### D14. HTTP/browser payloads could claim the internal channel
- **Expected**: `channel` is transport-decided — HTTP always forces
  `user` and rejects `channel:'internal'` in the body; internal commands
  require a trusted in-process seam plus `expectedInternalRevision`.
- **Observed**: `body.channel`/`runnerId` could be forged by a browser.
- **Resolution**: `service.request` forces channel=user and rejects
  `channel:'internal'`; `service.internalCommand()` is the only internal
  path (no HTTP route) and requires `expectedInternalRevision`; internal
  dedup keys use an `i:` prefix, isolated from user commandIds.
- **Status**: resolved — `revisions: heartbeat moves only
  internalRevision via trusted seam`.

### D15. Repair ran only at startup/before GET
- **Expected**: durable projections/intents are repaired before managed
  AND legacy writes too, with CAS consistent with repaired revisions.
- **Observed**: `repairNow` only ran at init and before managed GETs —
  same-process writes after a partial crash bypassed repair.
- **Resolution**: `repairState` is the front step of the serialized queue
  — every write, command, and managed/legacy read passes through it;
  repaired doc revisions participate in normal CAS.
- **Status**: resolved — covered by the injected-fault crash tests.

## HTTP adapter (acp-state-server.mjs)

### D16. Env names and CORS regressed vs the deployed contract
- **Expected**: keep `STATE_DIR`/`PORT` (compose sets them); wildcard
  CORS `*` preserved plus POST; comment claiming a `/data` container
  mount was false for current compose.
- **Observed**: new adapter read `ACP_STATE_DIR`/`ACP_STATE_PORT`; CORS
  echoed `Origin`+`Vary`; header comment described a nonexistent `/data`
  mount.
- **Resolution**: `resolveConfig(env)` reads `STATE_DIR`
  (default `~/.hermes/acp-ui-state`) and `PORT` (default `25900`) and is
  an import-safe config seam; CORS origin `*`, methods include POST;
  comment corrected.
- **Status**: resolved — `config seam: STATE_DIR/PORT legacy env names
  and defaults`.

### D17. Over-limit bodies returned 500; declared Content-Length unchecked
- **Expected**: >5MiB → 413 for both declared `Content-Length` and
  streamed over-limit; malformed URL → 400.
- **Observed**: streamed over-limit threw a generic error → 500; a
  declared `Content-Length` over the limit was only caught after the body
  actually streamed past; malformed URL → 500.
- **Resolution**: `readBody` raises `PAYLOAD_TOO_LARGE` → 413; the
  handler checks declared `Content-Length` before reading, drains the
  socket, then 413; URL parse failure → 400.
- **Status**: resolved — `http: over-5MiB bodies -> 413 (declared length
  and streamed)`, `http: OPTIONS, CORS '*' + POST, bad URL 400, unknown
  route 404`.
