## D1 — preparation fs preflight scratch dir missing (parent-found, fixed)

- **Expected:** preparation probe preflight passes on a provisioned host.
- **Observed (parent fresh tests):** probe failed `root_missing` for
  `/tmp/compound-engineering-1001`; after host
  `mkdir -m700` provisioning all 23/23 checks passed again.
- **Root cause:** `resolveRoots(binding, ws, {scratch:true})`
  (`server/execution/preparation/skills/registry.mjs:547-552`) adds the
  per-uid ce scratch root `ceScratchRoot()` (`registry.mjs:508-514`:
  `<TMPDIR|os.tmpdir()>/compound-engineering-<uid>`) to the write set, and
  `preflightBinding(..., fsCheck:true)` (`preflight.mjs:141-153`) refuses
  with `root_missing` when any declared root is absent. Nothing creates
  the dir — it is a host provisioning duty. No code bug.
- **Reproduced here (lead worktree):** moved the live dir aside →
  `preparation_binding_probe.mjs preflight ce-brainstorm --ws /tmp`
  EXIT:1 `root_missing ... /tmp/compound-engineering-1001`; restored →
  `preflight ce-brainstorm --ws /tmp/compound-engineering-1001` EXIT:0
  (digest b6a7ba03578c22e). Evidence: /tmp/probe_missing.log, /tmp/pf2.log
  (host-local, not committed).
- **Resolution:** provisioning step added to `deploy/COMPOSE.md`
  ("Host provisioning"): `install -d -m 0700 -o 1001 -g 1001
  /tmp/compound-engineering-1001`. Preflight stays fail-closed — no
  bypass, no code change in parent-owned preparation modules.
- **Remaining risk:** none in owned scope; /tmp is cleared on reboot, so a
  host without the provisioning step fails closed again (by design).
