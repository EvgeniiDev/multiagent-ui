# Восстановление мостов — 20 октября 2026

## Причины

При исходной проверке Devin (:25903), Hermes (:25901) и OpenCode (:25902)
не слушали порты. Pi и Codex работали. Выбранный режим — host.

Журнал Devin фиксирует в 14:10:49 UTC прямой общий `systemctl --user restart`
пяти host units, запущенный предыдущим агентом. После этого три units
бесконечно повторяли ExecStartPre: каждый видел соседей в состоянии
`activating`, MainPID=0 и отклонял запуск. Это отказ запуска до обмена ACP,
а не подтверждение несовместимости нового протокола. Контроллер уже умел
последовательный запуск, но не восстановление такого частичного состояния.

Дополнительная проверка двух окон выявила независимый дефект replay:
`sessionOwner` менялся при втором session/load той же сессии. Первое окно
получало неполную историю, второе — части обоих replay. Регрессионный тест
до исправления получил 5/60 и 115/60 фрагментов вместо 60/60 в каждом окне.

## Исправления

- `scripts/acp-bridges.mjs recover-starts --accept-interruption` отменяет
  незавершённые запуски только известных host units без MainPID и слушателя,
  сбрасывает сохранённые failed-состояния и запускает мосты последовательно.
  Работающие мосты не останавливаются. Проверки портов, режима, неизвестных
  владельцев и блокировка контроллера сохраняются.
- Повторные load/resume одной сессии проходят последовательно. Replay
  принадлежит своему запросу до ответа, включая закрытие исходного сокета.
  Request-id остаются разделены по сокетам; разные сессии независимы.
