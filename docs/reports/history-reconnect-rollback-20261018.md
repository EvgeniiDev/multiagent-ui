# Откат чата к старой истории при переподключении

Пользователь сообщил о старых сообщениях, выглядящих как текущая работа,
после переключения вкладок в Codex-сессии
`01a14af4-95f1-7af0-9848-df1585865f19`.

## Подтверждённый путь

`resume()` уже открытого runtime безусловно гидратировал локальную, затем
общую копию истории. При устаревшем кеше это заменяло более новые сообщения
в памяти старым текстом до окончания `session/load`. При возвращении во
вкладку пользователь видел именно этот старый снимок. Одновременно
`isLoading` использовался и для восстановления, и для генерации: последний
старый ответ получал streaming-caret и статус Working. Исторические кадры
также безусловно вызывали `notifyActivity`, зажигая unread.

Регрессионный тест до исправления показал точную подмену: вместо текущего
четырёхсообщенческого transcript оказался один `yesterday answer` из кеша.
Обычное переключение без потери транспорта в указанной реальной сессии
само по себе сбой не повторило: новых session/load не было, позиция
сохранялась. Для потери связи и устаревшего кеша воспроизведение устойчиво.

## Исправление

- При восстановлении той же уже открытой сессии сохраняется видимый transcript.
  Кеши используются только для холодного открытия. Старые replay-prefix
  остаются в отдельном буфере до подтверждённого окончания session/load.
- Для согласования DOM-идентичности используется прежний лимит 100 последних
  сообщений; он теперь общий для кеша и reconnect. Индекс инструментов
  перестраивается отдельно, не меняя видимые копии инструментов.
- UI показывает Restoring history, без таймера генерации и streaming-caret.
  RPC-флаг исторических кадров отделён от флага ожидания всей UI-операции:
  настоящие события после load-ответа продолжают попадать в activity/unread,
  даже если сохранение метаданных задержалось.
- Исторические кадры больше не помечают вкладку непрочитанной.
