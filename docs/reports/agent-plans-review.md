# Ревью четырёх агентских планов

Дата: 2026-10-01. По одному read-only субагенту на план. Проверены документы, связи с ядром и релевантные исходники/установленные навыки. Реальные CLI/контейнерные прогоны не выполнялись. Внесённые ниже исправления проверены ведущим по тексту и связям документов; повторного независимого ревью исправленных версий не было.

## Результат

Десять actionable замечаний: Fusion — 2, оркестратор — 3, Swarm — 3, подготовка идеи — 2. Все внесены в планы как уточнения согласованного поведения. Обязательных новых продуктовых вопросов не выявлено. Реальная совместимость среды и навыков остаётся входным гейтом реализации, а не доказанным результатом этого ревью.

| План | Замечание | Исправление |
|---|---|---|
| Fusion | Git linked worktree не работает без общего git-dir | Приватный Git worker, доверенный импорт полного результата в каноническую ветку, тест рестарта |
| Fusion | Egress не доказывает наличие поиска у модели | Capability и реальный search probe для CLI/образа/модели, preflight состава |
| Оркестратор | Worker Git мог открыть чужие refs | Приватные автономные repositories без shared git-dir/alternates/hardlinks |
| Оркестратор | Разрешение конфликта могло потеряться в финальной сборке | Immutable IntegrationArtifact и provenance, повторное использование принятого resolution |
| Оркестратор | Незакоммиченные результаты не попадали в diff commits | Полный immutable resultCommit до проверки, включая новые файлы и удаления |
| Swarm | Freeze не закрывал гонку start/apply и recovery | Worktree barrier, durable worker identities, подтверждения freeze, recovery/thaw и порядок cancel |
| Swarm | Не учитывался executable bit | Git modes 100644/100755, mode preconditions, журнал/rollback и chmod-only |
| Swarm | Не определён возврат замечаний владельцам | Маршрутизация владельцам, возврат рабочей фазы, запрет записи при проверке, общие лимиты |
| Подготовка идеи | Требования/план могли считаться ready при открытом гейте навыка | Durable SkillGate с binding/digest и предъявленной версией, проверки readiness/start |
| Подготовка идеи | Реальные навыки требуют filesystem/Git/handoffs, несовместимые с одной read-only проекцией | P0 feasibility, приватная document workspace, реальные операции и обязательные handoffs, допуск только доказанных routes |

## Остаточные ограничения

- Проверить container-runtime и реальные возможности CLI при реализации Fusion F1.
- Проверить filesystem/approval/handoff каждого начального skill binding в подготовке P0. Unsupported route нельзя показывать доступным или подменять имитацией.
- Git isolation, freeze/recovery и SkillGate пока являются требованиями плана, а не реализованными гарантиями.
- Сохранённые планы и отчёт не означают запуск фоновой реализации; она в этом чате не запускалась.

## Изменение архитектуры после ревью

После независимого ревью пользователь выбрал постоянную основу Pi и отдельные конфигурации ролей вместо универсальной поддержки разных CLI. Четыре плана обновлены этим решением, проверки переведены на Pi-профили; разнообразие моделей Fusion сохраняется. Основание — документация установленного Pi 0.85.1: отдельная config directory, явные skills/extensions, tool allowlist и RPC extension UI. Реальный запуск настроенных профилей ещё не проверен. Это уточнение после ревью не проходило повторное независимое ревью.

## Повторное ревью после выбора Pi profiles

Дата: 2026-10-01. Четыре независимых read-only субагента, по одному на план. Проверены актуальные документы, релевантные контракты ядра и установленная документация Pi. Реальные прогоны не выполнялись. Семь существенных P2 подтверждены ведущим и исправлены; новых продуктовых решений пользователя не требуется. Исправленные формулировки проверены ведущим, отдельный третий круг ревью не запускался.

| План | Исправление после второго ревью |
|---|---|
| Fusion | Search capability зависит от digest полного эффективного профиля, включая extensions/tools/allowlist. Удаление search tool инвалидирует probe. |
| Fusion | Dependencies готовятся по approved setup/lockfiles в отдельной ограниченной setup-среде; контроллер с Docker socket не выполняет код проекта. Проверяется реальная сборка и смена lockfile. |
| Оркестратор | Канонический resolution по точным inputs/порядку сборки переиспользуется всеми потребителями; пересекающиеся artifacts проверяются на совместимость. |
| Оркестратор | Completion/verification/integration проверяют поколение входов; поздний результат не возвращает stale узел в accepted. |
| Swarm | Полномочия привязаны к attempt/turn/поколению, отзываются при terminal/deadline/stop; durable apply recovery отдельно от новых команд. |
| Swarm | Подтверждение относится к immutable ревизии текста и круга участников; старые ack не утверждают новую ревизию. |
| Подготовка идеи | Native RPC диалог получает matching extension_ui_response в живую попытку; только завершённый вопрос переносит ответ в следующий prompt. Recovery создаёт новую RPC identity. |
