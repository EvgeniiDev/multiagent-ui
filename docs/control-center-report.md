Панель: http://192.168.1.222:25808 (systemd user unit `acp-ui-web`, раздаёт `dist-web/`).
Исходники: `~/projects/acp-ui`, ветка `control-center`. Требования — `docs/control-center-requirements.md`,
план — `docs/control-center-plan.md`. В `origin` ничего не пушилось.

## Функциональные требования

- **F1 оболочка и навигация — сделано.** Рейка из четырёх видов, состояние вида в KV
  (`preferences.json`), цифры 1–4 переключают виды и **игнорируются при вводе в поле** (проверено
  E2E: набор «3» в поиске не переключает вид). `⌘/Ctrl+K` — палитра команд остаётся в чате.
  Отличие от требований: Settings остался оверлеем, а не табом рейки — он и был модальным экраном,
  и ломать привычный вход через шестерёнку ради симметрии не стали.
- **F2 Projects — сделано.** Проект = рабочий каталог сессий (`cwd`), ничего не вводится руками.
  Плотные строки: индикатор «идёт работа», имя, путь (моно), агенты, число сессий, токены за
  диапазон, штамп времени. Детальная панель: метрики (сессии / последняя активность / токены /
  ходы / стоимость), список сессий проекта с открытием в чате, «New session here» (создаёт сессию
  в этом каталоге тем агентом, который в проекте работал). Фильтр по агенту + поиск по имени/пути.
- **F3 канбан — сделано.** Колонки `inbox · ready · blocked · active · review · done · cancelled`,
  строка-сводка в шапке в формате референса (`ready 2 (1 blocked)`), счётчики реагируют на фильтр.
  Карточка: заголовок, описание, проект, агент, приоритет, **критерии приёмки и шаги верификации**,
  ссылки, привязка к сессии (кнопка «Open session» возобновляет её и открывает чат). Drag&drop +
  меню «Move to» + `Alt+←/→`; сайд-дровер с автосохранением; персистенция в `board.json`
  (version + cards, debounce 600 мс, flush на `pagehide`) — карточки выживают перезагрузку.
- **F4 вкладки доски — сделано.** `Agents` (транспорт, состояние, текущая сессия, последнее событие,
  блокировки/ошибки за 24 ч), `Locks` (записи `lock` с PID держателя, если агент его прислал),
  `Timeline` (14 дней: токены/стоимость/ходы по дням, раскрытие дня в события), `Events` (живой
  поток, окно последних 200 строк, фильтры по виду и агенту).
- **F5 Dashboard — сделано.** Диапазоны Today/7d/30d/All, сводка (токены, стоимость с группировкой
  по валютам, ходы, сессии, tool-calls), таблицы по агентам и проектам, свой SVG-график по дням
  (нулевые дни заполняются, пустой набор даёт пустое состояние, а не сломанную ось), топ-10 сессий
  по расходу, блок **Limits** (квоты с областью «агент/проект/глобально», периодом и warning >90 %,
  персистенция в `limits.json`), экспорт JSON/CSV клиентским Blob.
- **F6 живое состояние — сделано частично, честно помечено.** Строка состояния агентов и
  `liveSessions` («ход начался и не закончился — в пределах, которые видит этот клиент»);
  доступность выводится из транспорта агента, а не из живого пинга моста — пинга в session store нет.
- **F7 сессии и вложения — сохранено** из предыдущей ночи (инвентарь `session/list`, лоадер при
  переключении агента, вложения как блоки у сообщения, включая восстановление из реплея).
- **F8 проект как юнит работы — сделано** (см. F2: сессии проекта, индикатор работы, запуск новой
  сессии в каталоге проекта). Привязка карточек доски к проекту есть в полях карточки; сводного
  «карточки этого проекта» на панели проекта нет — это следующий шаг, а не забытая галочка.

## Нефункциональные требования

- **N1 адаптивность — сделано, с замерами.** 1440/1024/390: горизонтального скролла страницы нет ни
  на одном виде; на телефоне рейка — верхняя полоса 390×57, доска переключает колонки
  сегмент-контролом, таблицы дашборда становятся строками с подписями. Тач-цели: аудит нашёл
  22/28/30 px (доска и фильтры Projects) — исправлено до ≥44 px (`cc/polish`), проверено заново:
  при 390×844 ни одного интерактивного элемента ниже 44 px. Ровно тот дефект, который и должен
  был найти независимый аудит: агентские E2E у обоих воркстрим были зелёные.
- **N2 дизайн-система — сделано.** Текст на всех четырёх видах только палитрой токенов
  (`rgb(43,39,35)`, `rgb(163,154,142)`, `rgb(107,98,89)`, `rgb(194,83,47)`, `rgb(251,248,243)`);
  теней — ноль; эмодзи-иконок — ноль (10 файлов переведены на stroke-SVG в `currentColor`);
  появился токен `--text-on-accent` вместо шести голых `#fff`. Проверено программно
  (`getComputedStyle` в playwright), потому что vision-инструмент в этой сессии не отвечал.
- **N3 данные — сделано.** Только локальный KV (localStorage на web / Tauri store на десктопе),
  версионированные ключи (`board.json`, `limits.json`, `activity.json`, `preferences.json`),
  ни одного внешнего запроса и никакой телеметрии.
- **N4 производительность — сделано в разумных пределах.** События окном (200 строк), списки
  плотные, тяжёлых синхронных проходов в рендере нет; 24 сессии/131 сессия разных агентов
  синкаются за 0.02–0.32 с.
- **N5 сборка и типы — сделано.** `npm run build:web` (строгий `vue-tsc` + vite) зелёный после
  каждого слияния; новых рантайм-зависимостей нет — график написан своим SVG.
- **N6 язык UI — сделано** (английский, короткие строки, никаких простыней).
- **N7 доступность — частично.** `aria-label` на иконочных кнопках, `focus-visible`, `aria-live`
  на загрузках, семантика `<table>`, доска управляется с клавиатуры (`Alt+←/→`, `Esc`); полного
  аудита скринридером не делал.
- **N8 совместимость — сделано** (Web-сборка на LAN; Node-API в рендерере не используются).
- **N9 честность цифр — сделано.** Пустые состояния объясняют, что сделать; токены/стоимость
  берутся только из `usage_update`, ничего не досчитывается «примерно»; окно данных подписано.
- **N10 верификация — сделано.** У каждого воркстрима свой playwright-E2E по реальному бандлу и
  скриншоты трёх вьюпортов; приёмка перепрогоняет всё на слитом дереве (`scripts/e2e_all.py`).

## Что нашли и починили именно на приёмке

1. Мёртвое условие дедупликации `usage_update` (`!(a) !== !(b)` всегда false) — теперь
   пропускается только точный повтор сэмпла по сессии (`b90f750`).
2. Подложка drawer'а показывалась на Projects/Board/Dashboard после ресайза — добавлена проверка
   активного вида (`b90f750`).
3. События карточек шли видом `sync`, путаясь с синками сессий — введён `ActivityKind: 'card'`
   (`b90f750`).
4. Телефон: строка-сводка доски вылезала за бокс (488 px в 302 px), тач-цели 22–30 px, фильтры
   Projects 28 px (`cc/polish`, `862ec77`).
5. 24 эмодзи-иконки в 10 файлах — переведены на SVG (`cc/icons`, `5634cbf`).
6. Тёмная тема: 13 пар «текст/фон» ниже порога WCAG — см. следующий раздел.

## Тёмная тема (последний пункт ночи)

Замер с композитингом слоёв (мелкий текст — порог 4.5:1) дал в тёмной схеме: мутед-текст
3.23–3.56:1, светлый текст на заливке акцента 2.92–3.10:1, акцент-как-текст на 16 %-подложке
3.86–3.88:1. Светлая схема — ноль провалов. Причина на уровне токенов: `--text-muted` слишком
тёмный для тёмных поверхностей, `--text-on-accent` в тёмном блоке не переопределён (осталась
бумага, а акцент там светлый), `--text-accent` на подложке не дотягивает. Задача ушла отдельным
брифом (`cc/dark2`) с посчитанными значениями-кандидатами; результат и его проверка — в
`docs/reports/dark-report.md`, когда ветка смёржена. Первый прогон этой задачи (Devin) потратил
весь бюджет на разведку и не оставил коммита — приёмка это поймала (`cc/dark` пуст), задача
перевыпущена по-другому: с готовым диагнозом и без права на исследование репозитория.

## Контраст и доступность (замеры с композитным фоном, обе схемы)

Аудит считает фон обходом предков со сбором всех слоёв с alpha>0 и композитингом снизу вверх
(`out = top*top.a + out*(1-top.a)`) — иначе полупрозрачные подложки и `body` с `rgba(0,0,0,0)`
дают ложные «1.0:1» и прячут реальные провалы. Порог: 4.5:1 для мелкого текста.

| Что | До | После |
|---|---|---|
| Тёмная схема, мутед-текст на тёмных поверхностях | 3.23–3.56:1 | **6.44 / 7.10:1** (`--text-muted: #b3a79b`) |
| Тёмная схема, светлый текст на заливке акцента | 2.92–3.10:1 | **5.40:1** (в тёмный блок добавлен `--text-on-accent: #211d1a`) |
| Тёмная схема, акцент-как-текст | 3.86–3.88:1 | **7.32:1** (`--text-accent: #f0a184`) |
| Светлая схема, мутед-текст (∼сотня элементов) | 2.49–2.62:1 | **4.76:1 на бумаге / 4.52:1 на сайдбаре** (`--text-muted: #786d62`) |
| Шесть правил с голым `color: white` на заливках | игнорировали токен | идут через `var(--text-on-accent, …)` |

Итог замеров после правок (`cc/accent`, коммит `d8856d0`): **обе схемы — 0 провалов** на всех
четырёх видах. Акцентные пары закрыты двумя значениями токенов: `--text-on-accent` `#fbf8f3` →
`#ffffff` (4.34 → **4.59:1** на заливке `#c2532f`) и `--text-accent` `#c2532f` → `#b04a28`
(**5.14:1** на бумаге, **4.53:1** на 16 %-подложке). Заливка брендовой терракоты `--bg-primary`
не менялась — отличаются только текстовые роли акцента.

Все эти провалы нашла приёмка, а не исполнители: их собственные E2E были зелёными.

## Чего сознательно нет

- Бесконечный canvas терминалов (CanvasTTY из комментариев) — отдельный продукт, не эта итерация.
- Никакой серверной части, аккаунтов, командной работы на несколько машин (только локальные
  данные и локальные мосты).
- Картинки из истории сессии по-прежнему без превью: агенты не возвращают в реплей ни байты,
  ни маркер изображения (замерено на OpenCode и Hermes).
- Сводка «карточки этого проекта» на панели проекта и пинг доступности мостов — следующие шаги.

## Как перепроверить самому

```bash
cd ~/projects/acp-ui
npm run build:web                                  # строгий vue-tsc + vite
~/.hermes/tools-venv/bin/python scripts/e2e_all.py # все четыре набора E2E на одном снимке
```

Живая панель: http://192.168.1.222:25808 — четыре вида переключаются рейкой или цифрами 1–4,
на телефоне тот же адрес открывается в портретной ориентации.
