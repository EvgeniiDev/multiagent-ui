# Control Center — требования (черновик к утру)

Источник: пост @llm_under_hood [942](https://t.me/llm_under_hood/942) + 43 комментария к нему (включая 6 комментариев со скриншотами). Панель = наш форк acp-ui, дальше развиваем её в «control center для команды из людей и агентов».

## Что именно просят в референсе

Пост 942 (автор канала): он попросил Codex переписать свой web-таск-менеджер в **нативное** macOS-приложение; на скриншоте — список задач, статус коммита, «Working tree is clean», трекер уровня подписки. Дальше его вывод дословно:

> «можно аналогичным образом сделать **нативный control center для команды из людей и агентов** под текущие задачи, входящую статистику, дашборды и тому подобное. И чтобы было красиво и на ноутбуке, и на планшете, и на телефоне.»

И вопрос читателям: «Если у вас уже есть такие control centers, скидывайте их скриншоты в комментарии!» — то есть панель нужна не «чат с агентом», а **пульт управления работой людей и агентов**.

### Что показали в комментариях (это и есть «все идеи»)

- **`loopyard` / capos Board** (скрин в комментарии 4) — самая близкая к запросу панель. Табы: **Tasks · Agents · Locks · Timeline · Events**. Счётчики на табе Tasks: `ready (6 blocked)`, `active`, `review`, `done`, `canceled`, `On-HOLD`. Карточки задач с полями: `path …` (несколько путей!), `resource …`, `evidence …` (например `gce-public-web`, `cloudboot-harn`), `project …`, `agent …`, приоритет (`+ high`/`+ medium`), статус (`ready`/`blocked`/`active`/`review`/`done`). Внизу — `connecting A local` (индикатор связи). Задачи выглядят как **работа агентов над репозиториями**, а не как личные тудушки.
- **Второй скрин-набор (комментарий 3)** — доска задач с **критериями приёмки и шагами верификации** прямо в карточке (acceptance criteria, «run the QEMU proofs through pytest instead of …», параметризация, «focused context … pause/stop cases»), т.е. карточка = бриф + проверка.
- **CanvasTTY** (комментарий 16, [github.com/howdeploy/CanvasTTY](https://github.com/howdeploy/CanvasTTY)) — «бесконечный canvas, на котором можно собирать рабочее пространство из терминалов», автор использует как единый workspace для агентов: **много харнессов из коробки в один клик + отслеживание лимитов**, вместо пачки отдельных окон.
- **Комментарий 2/10/21** — методология: харнес = «агент + дерево документов (пирамида концепций) + исполняемые спеки»; требования руками, спеки агентом, код агентом; разработка «сверху вниз».
- **Комментарий 12** — правило подачи: никаких простыней, только короткое описание + скриншоты + ссылка. (Учитываем в UI: плотные строки, никакого полотна.)
- **Комментарии 6/9/11/19/20/22** — дискуссия про «расслопливать код» и доверие к моделям; практический вывод для нас: панель должна **показывать фактическое состояние** (что агент сделал, где код, какие проверки прошли), а не пересказывать.

## Функциональные требования

Порядок = приоритет. ID: F<n>.

- **F1. Оболочка и навигация.** Левая рейка-навигация с табами: **Chat · Projects · Board · Dashboard · Settings**. Горячие клавиши 1–5 для переключения табов, `⌘/Ctrl+K` — командная палитра, `Esc` — закрыть оверлей. В шапке — текущий агент и текущий проект (cwd) как контекст.
- **F2. Projects (вкладка проектов).** Проекты определяются автоматически по рабочему каталогу сессий (`cwd`), без ручного ввода. Список проектов: имя (последний сегмент пути), путь, число сессий, последняя активность, какие агенты в нём работали, индикатор «идёт работа». Детальная панель проекта: сессии проекта (открыть/возобновить/новая сессия в этом каталоге), сводка по проекту (сессии за 7/30 дней, токены и стоимость, активность по дням), быстрые действия. Фильтр по агенту и поиск по имени/пути.
- **F3. Board (канбан).** Колонки: **Inbox · Ready · Blocked · Active · Review · Done · Cancelled**. Карточка: заголовок, проект, агент-исполнитель, приоритет (`high/medium/low`), описание, **критерии приёмки и шаги верификации** (как на скрине комментария 3), привязка к сессии (клик — открыть сессию в чате), вложения/ссылки. Drag&drop между колонками, счётчики по колонкам в шапке, создание/редактирование/удаление карточки. Карточки персистятся локально.
- **F4. Board → вторичные табы.** `Agents` (живой статус каждого агента: мост доступен, занят/простаивает, текущая сессия и что делает), `Locks` (сессии, удерживаемые другим процессом: из ошибки `session_locked` + активные ходы; с PID, если агент его прислал), `Timeline` (хронология активности: сессии/ходы/карточки по дням), `Events` (живой лог событий: старт сессии, ход, tool-call, ошибка, смена статуса карточки).
- **F5. Dashboard (статистика и лимиты).** Считаем по факту, из протокола: ACP присылает `usage_update` (`used`/`size`/`cost`) и `session_info_update`. Показываем: токены и стоимость по агентам, проектам, дням; число сессий и ходов; топ-N сессий по расходу; диапазоны «сегодня / 7 дней / 30 дней / всё». Отдельный блок **Limits** — как трекер подписки в референсе: настраиваемые квоты на агента/проект с прогресс-барами и предупреждением при приближении к лимиту. Экспорт в JSON/CSV.
- **F6. Живое состояние.** Индикатор доступности каждого моста (ws-подключение), текущее состояние хода (idle / streaming / waiting-permission), очередь запросов, время последнего ответа. Ошибки агентов — не тост на 3 секунды, а строка в Events с текстом агента (как `session_locked` с PID).
- **F7. Сессии и вложения (уже есть, сохранить).** Инвентарь сессий агента (`session/list`), скоуп по агенту со сбросом и лоадером, вложения (картинки/текстовые файлы) как блоки у сообщения, восстановление вложений из реплея истории.
- **F8. Работа с проектом как с юнитом работы.** В проекте видно: какие агенты в нём работают сейчас, какие сессии открыты, какие карточки доски к нему привязаны, и кнопка «новая сессия в этом проекте» с выбором агента.

## Нефункциональные требования

- **N1. Адаптивность.** Три диапазона: laptop ≥1280, tablet 768–1279, phone <768. На планшете/телефоне рейка сворачивается в drawer, доска — в вертикальные колонки/свайп, таблицы — в строки-карточки. Никакого горизонтального скролла. Тач-цели ≥44px.
- **N2. Дизайн-система.** Только токены из `App.vue :root` (27 штук), никаких хардкод-цветов; одна акцентная терракота `#c2532f`; плоско, хайрлайны, без теней и градиентов; **без эмодзи в роли иконок** (stroke-SVG в `currentColor`); машинный текст — моно; плотные однострочные списки вместо карточек там, где это список. Контраст текста ≥4.5:1.
- **N3. Данные и приватность.** Всё состояние — локальный KV-стор (localStorage на web, Tauri store на десктопе). Никаких внешних запросов, никакой телеметрии по умолчанию, никакого бэкенда. Ключи версионировать, чтобы обновления не ломали старые данные.
- **N4. Производительность.** 200+ сессий, 1000+ событий, 100+ карточек без лагов: окна/виртуализация там, где список длинный; первый рендер <1 с в локальной сети; никаких длинных синхронных циклов в рендере.
- **N5. Сборка и типы.** `npm run build:web` (vue-tsc strict + vite) проходит; новых рантайм-зависимостей не добавлять без обоснования (графики — свой SVG, не chart-либа).
- **N6. Язык UI.** Английский, как в текущих экранах; тексты короткие, без «простыней» (правило комментария 12).
- **N7. Доступность.** Фокус-состояния, навигация с клавиатуры (табы, доска, диалоги), `aria-label` на иконочных кнопках, `aria-live` на лоадерах.
- **N8. Совместимость.** Работает и в web-сборке (LAN, http), и в Tauri-десктопе: никаких Node-API в рендерере, fs — только через host-абстракцию.
- **N9. Честность цифр.** Никаких выдуманных метрик; если данных нет — пустое состояние объясняет, что сделать; каждая цифра имеет источник (сессия/агент/день).
- **N10. Верификация.** На каждую фичу — playwright-E2E по реальному бандлу + скриншоты для трёх вьюпортов; результат фиксируется в отчёте.

## Границы (что НЕ делаем этой ночью)

- Никаких изменений на стороне агентов и мостов (только клиент); серверные/облачные синки, аккаунты, командная работа «на несколько машин» — вне скоупа.
- Замена терминала (CanvasTTY-подобный бесконечный canvas) — отдельная тема, не в этой итерации.
