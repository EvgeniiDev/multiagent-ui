# Control Center v2 — план работ

Требования: `docs/control-center-v2-requirements.md` (+ решения владельца в §F).
Правила параллельной работы — прежние: один воркстрим = один worktree + ветка, файлы-владельцы
закреплены, чужие файлы трогать нельзя (нужное — в `## Integration requests`), E2E по реальному
бандлу, приёмка Hermes-ом с независимыми замерами.

## Порядок

### Волна 1 (параллельно)

| # | Воркстрим | Суть | Исполнитель | Ветка / worktree |
|---|---|---|---|---|
| W1 | **Реестр проектов** | Settings → Projects: список, создание папки по пути, указание существующей; проект `{id,name,path,…}`; автопроект `Common` → `~/projects`; правки `sessionStore` минимальные и ТОЛЬКО через Integration requests | Pi CLI | `cc/v2-projects` |
| W2 | **Глобальный селектор проекта** | селектор в шапке (All + проекты), скоуп сессий/Projects-вида; сессии проекта слева полным списком (старый вид, отфильтрованный) | Devin CLI | `cc/v2-scope` |

Конфликтная зона: оба трогают шапку/сторы → W1 владеет `stores/projects.ts` и Settings-секцией,
W2 владеет `stores/ui.ts` (scope) и шапкой; интеграция стора проектов в селектор — на приёмке.

### Волна 2 (после слияния волны 1)

| # | Воркстрим | Суть | Исполнитель | Ветка |
|---|---|---|---|---|
| W3 | **Канбан-конвейер** | стадии Backlog/Spec/Plan/Dev/ReviewTest/Done, статусы внутри (in_progress/review/done; у ReviewTest: in_progress → agent_tested → accepted), флаги blocked/cancelled, фильтр по проекту + All, миграция `board.json` (version+1) | Devin CLI | `cc/v2-board` |
| W4 | **Дашборд по проекту** | скоуп по селектору + All, расход по ролям (когда появятся роли) | Pi CLI | `cc/v2-dashboard` |

### Волна 3

| # | Воркстрим | Суть | Исполнитель |
|---|---|---|---|
| W5 | **Роли + диспетчер** | роль = {executor, model, prompt-файл в проекте}, привязка к стадии, claim/lease/heartbeat, авто-режим разрешений (auto-approve + аудит), handoff-блок, evidence, лимиты, visible queue | Devin CLI |

W5 стартует после W3 (нужны стадии и статусы). Между волнами — сборка, полный E2E-прогон
(`scripts/e2e_all.py` + новые наборы), скриншоты трёх ширин.

## Контракты

- **Селектор проекта** — единственный источник скоупа: `stores/ui.ts` хранит `activeProjectId`
  (`'all' | projectId`), остальные сторы читают его computed'ом. Никто не хранит свою копию.
- **Реестр проектов** — `stores/projects.ts` + KV `projects.json` (version), автосоздание `Common`
  при первом запуске. Сессия связывается с проектом по `cwd` (как сейчас) — реестр не переписывает
  историю.
- **Канбан** — `stage` (backlog/spec/plan/dev/reviewtest/done) + `status` + флаги `blocked`,
  `cancelled`; миграция старой схемы описана в §E требований.
- **Дизайн-язык, N1–N10** — без изменений (токены, плотные строки, без эмодзи, E2E на трёх ширинах).
- **Запрещено всем:** менять `src/lib/acp-bridge.ts`, `dist-web`, чужие ветки; сетевые вызовы;
  `systemctl`.

## Приёмка (каждая волна)

1. Слияние в `control-center`, сборка, `scripts/e2e_all.py` + новые наборы воркстримов.
2. Независимый аудит: клик-проход по новым поверхностям на 1440/1024/390, нулевой pageerror.
3. Скриншоты в `docs/`, отчёт воркстрима в `docs/reports/`.
4. Запись в `~/.hermes/MODIFICATIONS.md`.
