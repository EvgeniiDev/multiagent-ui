# Workflow: опрос → план → тесты → оркестратор → изоляция

---

## Диагноз обычного пайплайна «дал промпт → жду»

1. Промпт без деталей — агент сам решает, что и как делать.
2. Нет критериев готовности — непонятно, когда закончил.
3. Агент теряет контекст по ходу работы.
4. Никто не проверяет код после выполнения.
5. Один агент на всё.

## Пять шагов

### 1. Опрос

Попросить агента задать уточняющие вопросы до работы (или спец-скилл). Ответы
превращают плоский промпт в глубокий. Ни один исходный промпт не покрывает все грани.

### 2. План + спецификация

- По итогам опроса — план.
- По плану — **спецификация**: долгоживущая память «что где как в проекте». Без неё
  агент каждый раз перечитывает файлы (забивает контекст) и галлюцинирует. Спека
  меняется вместе с проектом.

### 3. Тесты ДО кода

- Тест = ТЗ без двусмысленности. План говорит «сделай авторизацию», тест говорит
  «верный пароль → токен; неверный → 401; три неверных → блок на минуту». Это контракт,
  код пишется под него.
- Тесты после кода агент пишет под сделанное — всегда зелёные, проверяют не то.
- «Готово, всё работает» без запуска — вежливость, а не отчёт. Тесты превращают её
  в факт: красные = не готово, лезть в код самому не нужно.
- Команды из видео, дословно по смыслу:
  1. «Прежде чем писать код, составь тесты по спеке для каждого пункта плана:
     что проверяем, какой вход, какой ожидаемый результат. Запусти, убедись что
     красные (кода ещё нет — это норма)».
  2. «Теперь пиши код, пока все тесты не станут зелёными. После каждого изменения
     запускай сам. Упало — читай ошибку и чини, не спрашивай меня».
- Агент крутит цикл «написал → запустил → красное → починил → зелёное» — это и есть
  недостающая обратная связь. Ошибку находит сам агент сразу, а не ты потом.

### 4. Изолированные ветки

Копия папки проекта на задачу (git worktree): агенты работают параллельно, не ломают
main и не дерутся за файлы.

### 5. Оркестратор

- Умная модель режет план на подзадачи, раздаёт дешёвым воркерам, пишет **пункты
  валидации на каждую подзадачу** и следит за выполнением по своим критериям.
- Токены умной тратятся мало (сама не кодит), время выигрывается параллелизмом.

## Что из этого — в acp-ui

- Пункты валидации на подзадачу + отклонение воркера ≈ наш такт «ленивого техдира»
  (дорожный план п.3).
- Спека как долгоживущая память ≈ наш файл-план автопилот (п.4).
- Тесты-как-контракт подкрепляют наш пункт долгого ящика «спека как тест-система».
