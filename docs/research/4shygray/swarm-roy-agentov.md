# Swarm: рой равноправных агентов на одной ветке

---

## Что это

Агенты — равноправные члены роя, главного нет. Решения принимаются спором через
канал связи; зафиксированное «решение» обязательно для всех. Замер автора на одной
задаче (2 одинаковых воркера): swarm 11:12 против соло 20:22 — ~2x скорость,
качество паритет.

Заявленные цифры из видео (чужие бенчмарки, наших замеров нет): рой качественнее
одиночки, на сложных задачах — буст качества и скорости. Брать на тяжёлые длинные
задачи.

## Рой ≠ «N агентов на одну задачу»

Просто дать трём агентам одну задачу = три разные версии кода, которые не склеить.
Рою нужны 4 вещи:

1. **Одна общая цель вместо нарезанного плана.** Планировщика нет: все получают цель
   целиком и делят её между собой на ходу. (В оркестраторе наоборот — умная модель
   заранее режет на подзадачи и раздаёт.)
2. **Одна общая ветка / один каталог.** В отличие от изолированных копий оркестратора:
   участники видят правки друг друга в реальном времени; уведомление о чужой правке
   приходит до следующего шага.
3. **Канал связи.** Позывные (A, B…), сообщения конкретному или всем. Отдельный тип
   сообщения — «решение»: кто-то фиксирует, остальные обязаны подстроиться. Это и есть
   голосование — без бесконечных дебатов.
4. **Протокол из трёх фаз** (без него — гонка):
   - **Фаза 1 — координация.** Правки запрещены. Каждый читает репозиторий и рассылает
     всем: какую долю цели берёт, какие файлы трогает, какие контракты/типы/API/имена
     предлагает, один подход, один реальный риск. Видимый конфликт (один файл, один
     подход) — тут же делят или фиксируют решением.
   - **Фаза 2 — реализация.** Каждый пишет только свой кусок, не всю задачу.
   - **Фаза 3 — догон.** Сообщения, пришедшие пока агент был занят, копятся в ящике;
     освободился — прочитал, ответил или поправил указанное. Число раундов ограничено
     (иначе два агента переписываются до конца подписки).
5. **Правило тишины:** отвечать только по делу. «Принял / согласен / закончили» —
   молча работаешь. Без него рой превращается в чат.

## Разнородные модели

Панель можно собирать из разных моделей (условные Fable + Astra, Opus + Astra):
разное мышление даёт подходы, которых не было ни у кого по отдельности. В демо
автора обе стороны были одним Opus — отсюда паритет качества с соло.

## Что из этого — в acp-ui

- Альтернатива нашим изолированным копиям раннера: общая ветка + уведомления о чужих
  правках до следующего шага. Перекликается с открытым вопросом «Jujutsu vs
  git+worktree».
- Фаза координации с заявкой доли/файлов/контрактов — готовый шаблон стартового
  промпта для параллельных ролей.
- «Решение как обязательный тип сообщения» — кандидат в протокол диспетчера
  (сейчас диспетчер только запускает команды, такта проверки живых прогонов нет).
- Разнородные связки — возможный ответ на открытый вопрос «какая комбинация топовая».
