# ACP UI

Локальная панель для работы с ACP-агентами: чаты, история сессий, проекты,
доска задач, режимы разработки и статистика использования. Этот репозиторий —
самостоятельный проект; исходники и конфигурация здесь определяют его поведение.

## Запуск веб-панели

Из каталога проекта:

```sh
npm ci
npm run dev:web
```

Адрес сервера разработки выводится в терминале. Для сборки и локального просмотра:

```sh
npm run build:web
npm run preview:web
```

Веб-панель подключается к настроенным ACP-мостам и локальному state-серверу.
Статический frontend сам по себе не запускает агентов или backend.
В текущей установке web использует порт 25808, HTTPS-вход — 25809,
state — 25900. Панель открывается по адресу своего сервера.

## Работающая установка

Перед изменениями прочитать [AGENTS.md](AGENTS.md) и [TESTING.md](TESTING.md).
Сервисы описаны в `compose.yaml`; пять мостов управляются через
`scripts/acp-bridges.mjs` в явно выбранном Docker- или host-режиме.

```sh
node scripts/acp-bridges.mjs status
```

Мосты: Hermes, OpenCode, Devin, Pi и Codex. Исходник общего моста —
`deploy/acp-ws-bridge.mjs`. Не запускать параллельные экземпляры на их портах.

Для обновления работающей веб-панели сначала проверить фактический bind mount
контейнера `acp-ui-web-1`. Собирать frontend во временный каталог, копировать
assets в этот mount, а `index.html` заменять последним. Обычная frontend-сборка
очищает выходной каталог, поэтому не собирать напрямую в обслуживаемый `dist-web/`.
Перезапуск мостов при обновлении frontend не требуется.

## Данные и внешние подключения

Панель не содержит SDK внешней аналитики и не отправляет события использования,
ошибки или идентификатор устройства в сервис телеметрии. Локальная статистика
токенов, расходов и журнал активности остаются частью панели.

Подключения к настроенным агентам, модельным провайдерам и сервису распознавания
речи определяются их конфигурацией. Отсутствие аналитики не делает эти сервисы
офлайн. Автопубликация на GitHub Pages и workflow публикации релизов удалены;
CI проверяет сборку без публикации.

## Desktop и mobile

Поддержка Tauri сохранена в `src-tauri/`. Desktop поддерживает локальные stdio-агенты;
web и mobile используют сетевые подключения. Native-приложения собираются локально
с установленными инструментами соответствующей платформы.

Идентификатор новых native-сборок — `local.acp-ui`. При переходе со старого
идентификатора `formulahendry.acp-ui` хранилище настроек и данные WebView могут
оказаться в новом каталоге. Старые данные не удаляются и автоматически не
переносятся; перед заменой установленного native-приложения нужно сохранить
его настройки. Это не меняет данные веб-панели на сервере.

## Проверки

```sh
node scripts/test_codex_acp_initialize.mjs
```

Выбирать остальные проверки по затронутому пользовательскому сценарию согласно
[TESTING.md](TESTING.md). Проверять фактически опубликованную сборку в браузере.
