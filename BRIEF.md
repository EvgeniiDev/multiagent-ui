## Что требует владелец (дословно)

«Вижу колонки blocked active done — но это похоже на статусы. А у меня должна быть система с колонками
и со статусами у каждой карточки в колонке.» Плюс ранее: колонки-стадии `Backlog → проработка (Spec) →
планирование (Plan) → разработка (Dev) → review/тестирование → выполнена`, у Spec/Plan/Dev внутри
`in_progress → review → done`, у review — сначала агент тестирует, потом приёмка человеком,
подзадач нет (одна карточка, даже если её делают несколько субагентов).

## Модель (реализовать буквально)

- **Стадии (колонки), порядок:** `backlog` → `spec` → `plan` → `dev` → `reviewtest` → `done`.
- **Статус карточки внутри стадии** (`card.status`):
  - `backlog`: статуса нет (`null`);
  - `spec`, `plan`, `dev`: `in_progress | review | done`;
  - `reviewtest`: `in_progress` (агент тестирует) → `agent_tested` → `accepted` (человек);
  - `done`: терминальная, статус `null`.
- **Флаги карточки (не колонки!):** `blocked` (+ `blockedReason`, необязательно ссылка на карточку),
  `cancelled`. Флаг `blocked`/`cancelled` может стоять на карточке в любой стадии; такие карточки
  визуально помечены и **не участвуют в автозаборе** (задел под роли/диспетчер).
- **Поля под PM-роль** (F10.3, добавить в модель сейчас, логику не писать):
  `touches: string[]` (модули/пути), `dependsOn: string[]`, `blocks: string[]`, `conflictsWith: string[]`
  (массивы id карточек).
- **Миграция** старой доски (`board.json`, version 0/отсутствует): `inbox`→`backlog`; `ready`→`spec` +
  `in_progress`; `active`→`dev` + `in_progress`; `review`→`reviewtest` + `in_progress`;
  `done`→`done`; `cancelled`→`done` + флаг `cancelled`; `blocked`→`backlog` + флаг `blocked`.
  Карточки не терять; поднять `version` и санировать битые записи (как сейчас в `sanitizeCard`).
- **Скоуп проекта:** доска подчиняется глобальному селектору (`stores/ui.ts` →
  `activeProjectId`, читать только через него) + **кнопка All** на самой доске, чтобы увидеть карточки
  всех проектов. Карточка без проекта видна только в `All` (помечена как `unassigned`).
- **Подзадач нет.** Одна карточка = одна единица работы на всём пути.

## UI/UX

- Шапка стадии: название, счётчик карточек, и **разбивка по статусам** внутри (`spec 2 · in_progress 1 /
  review 1`), `blocked`-флаг считать отдельно (как раньше считался blocked-счётчик).
- На карточке: маленький чип статуса (`in_progress`/`review`/`done`/`agent_tested`/`accepted`),
  бейджи флагов (`blocked`, `cancelled`), и компактный контрол смены статуса **на самой карточке**
  (например клик по чипу → выпадашка со статусами этой стадии), без модалок.
- Перетаскивание между стадиями работает как сейчас; при переносе в стадию — статус ставится в её
  начальный (`in_progress`, для `done`/`backlog` — `null`), если у карточки не было статуса этой стадии.
- Колонки скроллятся независимо; никаких теней/градиентов/эмодзи; только токены приложения; на ≤800 px
  — переключатель стадий (как сейчас) и тач-цели ≥44 px.
